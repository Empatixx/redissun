## SortedSet

Redisson's rank ranges include both ends; redissun takes an exclusive Rust range, so `valueRange(a, b)` is `range(a..b + 1)`. Score ranges take any `f64` range, which covers Redisson's inclusive flags. Iteration uses `ZSCAN`, as in Redisson, so its order is not guaranteed.

| Redisson | redissun |
|---|---|
| `add(score, v)` | `insert(&v, score)` |
| `tryAdd(score, v)`, `addIfAbsent(score, v)` | `try_insert(&v, score)` |
| `addIfExists`, `addIfGreater`, `addIfLess` | `insert_if_exists`, `insert_if_greater`, `insert_if_less` |
| `addAll(map)` and the `addAllIf...` variants | `extend` and `extend_if_...` |
| `addAndGetRank`, `addAndGetRevRank` | `insert_and_rank`, `insert_and_rev_rank` |
| `addScore(v, d)` | `add_score(&v, d)` |
| `getScore(v)`, `getScore(list)` | `score(&v)`, `scores(&list)` |
| `rank(v)`, `revRank(v)`, `rankEntry(v)` | `rank(&v)`, `rev_rank(&v)`, `rank_with_score(&v)` |
| `first()`, `last()`, `firstEntry()`, `lastEntry()` | `first()`, `last()`, returning `(value, score)` |
| `firstScore()`, `lastScore()` | `first_score()`, `last_score()` |
| `pollFirst()`, `pollLast()` | `pop_first()`, `pop_last()` |
| `pollFirst(n)`, `pollLast(n)` | `pop_first_many(n)`, `pop_last_many(n)` |
| `pollFirst(time, unit)`, `takeFirst()` | `pop_first_wait().timeout(t)`, `pop_first_wait()` |

## HashMapCache

| Redisson | redissun |
|---|---|
| `put(k, v)` | `insert(&k, &v)` |
| `put(k, v, ttl, unit)` | `insert(&k, &v).ttl(ttl)` |
| `fastPutIfAbsent(k, v)` | `insert_nx(&k, &v)` |
| `remainTimeToLive(k)` | `entry_ttl(&k)` |

Both delete expired entries with a background task that is paced the same way. `put(k, v, ttl, unit, maxIdle, unit)` is `insert(&k, &v).ttl(ttl).max_idle(idle)`. `setMaxSize(n, mode)` is `set_max_size(n, mode)`, and `addListener(...)` is `events()` or `events_of(kinds)` followed by `recv()`. Redisson takes expiry times from the client clock; redissun takes them from the Redis server.

## Behavioural differences

- The lock owner is a client and a tokio task, not a thread.
- Unlocking goes through a guard value. Unlocking something you do not hold is `Error::LockNotHeld` instead of an `IllegalMonitorStateException`.
- `Vec::remove(i)` past the end is `Error::OutOfRange`, also for index 0. Redisson returns `null` for index 0.
- Values use a serde codec rather than Redisson's Java codecs, so data written by Redisson is not readable by redissun and the other way round.
- When a semaphore or latch changes, redissun wakes every waiter and each one tries again. Redisson wakes only as many as there are permits.
- The rate limiter reads the time from the Redis server. Redisson sends the time of the client.
- `RateLimiter` has no `keepAliveTime` setting yet.
