---
title: Loaders and writers
description: Read-through with a MapLoader and write-through with a MapWriter.
---

A map can sit in front of another store, such as a SQL database. A `MapLoader` fills the map on a miss: read-through. A `MapWriter` hands every change of the map to the store: write-through. This is Redisson's `MapOptions`; redissun has one trait for `MapLoader` and `MapLoaderAsync`, and one for `MapWriter` and `MapWriterAsync`.

## A loader

Implement `MapLoader` with plain `async fn`s. A blocking store calls `tokio::task::spawn_blocking` inside them.

```rust
use futures::Stream;
use redissun::{BoxError, MapLoader};

struct Users(sqlx::PgPool);

impl MapLoader<String, User> for Users {
    async fn load(&self, key: &String) -> Result<Option<User>, BoxError> {
        Ok(sqlx::query_as("SELECT * FROM users WHERE id = $1")
            .bind(key)
            .fetch_optional(&self.0)
            .await?)
    }

    fn load_all_keys(&self) -> impl Stream<Item = Result<String, BoxError>> + Send {
        futures::stream::iter(Vec::<Result<String, BoxError>>::new())
    }
}
```

Give it to the map's builder:

```rust
let users = client
    .hash_map_builder::<String, User>("users")
    .loader(Users(pool))
    .build()
    .await?;

let user = users.get("jirka").await?; // a miss asks the loader
```

`client.hash_map(name)` is the same map without options.

## When the loader is asked

| Method | The loader is asked |
|---|---|
| `get` | on a miss |
| `get_many` | for each missing key, one at a time, in the order of the keys |
| `contains_key` | on a miss; `true` when it loaded a value |
| `entry(&k)` | on a miss, under the lock the entry holds |
| `load_all()`, `load_many(&ks)` | always |
| iteration, `len`, `to_hash_map`, `random_*`, `contains_value`, `incr_by`, every write | never |

## The lock

A miss takes the key's lock, the lock `entry(&k)` and Redisson's `getLock(key)` take. It reads the key again and returns a value that arrived meanwhile. Otherwise it asks the loader and stores a `Some` value with the map's plain put. So ten gets of one missing key at once ask the loader once, and all of them see the value. A Redisson client loading the same key of the same map takes the same lock.

A loaded value is not handed to the map's writer: it came from the store. `None` stores nothing, and the next miss asks again.

## Errors

A failing loader gives `Err(Error::Loader(_))` with its error as the source. The map stores nothing and the lock is released, so the next call asks again. Redisson returns `null` instead.

## Load all keys

`load_all()` loads every key `load_all_keys` streams, Redisson's `loadAll(replaceExistingValues, parallelism)`. `load_many(&keys)` loads only those keys.

```rust
users.load_all().parallelism(4).await?;
users.load_many(&["jirka", "petr"]).replace_existing().await?;
```

| Option | Default | Redisson |
|---|---|---|
| `.parallelism(n)` | 1 | `parallelism` |
| `.replace_existing()` | keys the map holds keep their value | `replaceExistingValues = true` |

Each key is loaded as a miss is, under its lock. The load stops at the first error. Without a loader, or with `parallelism(0)`, it is an `Error::Config`.

## A writer

Implement `MapWriter` with plain `async fn`s and give it to the builder with `.writer(w)`. A map can have a loader and a writer, also the same value for both.

```rust
use redissun::{BoxError, MapWriter};

impl MapWriter<String, User> for Users {
    async fn write(&self, entries: &[(String, User)]) -> Result<(), BoxError> {
        for (id, user) in entries {
            sqlx::query("INSERT INTO users VALUES ($1, $2) ON CONFLICT (id) DO UPDATE SET name = $2")
                .bind(id)
                .bind(&user.name)
                .execute(&self.0)
                .await?;
        }
        Ok(())
    }

    async fn delete(&self, keys: &[String]) -> Result<(), BoxError> {
        sqlx::query("DELETE FROM users WHERE id = ANY($1)")
            .bind(keys)
            .execute(&self.0)
            .await?;
        Ok(())
    }
}
```

The keys within one call are unique and keep the order of the map call.

## When the writer is called

| Method | Writer call | When |
|---|---|---|
| `insert`, `set` | `write([(k, v)])` | always |
| `try_insert` | `write([(k, v)])` | it stored the value |
| `replace` | `write([(k, v)])` | the key was present |
| `compare_and_set` | `write([(k, new)])` | it returned `true` |
| `incr_by`, `incr_by_float` | `write([(k, new value)])` | always; the new number decoded as `V` |
| `remove` | `delete([k])` | always, also for a missing key, as in Redisson |
| `remove_if_eq` | `delete([k])` | it returned `true` |
| `remove_many` | `delete(removed keys)` | at least one key was removed |
| `extend` | `write(batch)` | once per `.batch_size(n)` batch |
| `entry(&k)` writes | `write([(k, v)])` or `delete([k])` | the entry writes or removes, under its lock |
| `clear`, `del`, loaded values | none | |

`remove_many` with a writer runs Redisson's `fastRemoveOperationBatchAsync` script to learn which keys it removed. Redisson calls `delete([])` when none was removed; redissun calls nothing.

## Write-through

Redis changes first, then the writer is called, as in Redisson. If the writer still fails after its attempts, the call returns `Err(Error::Writer(_))` with the writer's error as the source, and Redis keeps the change.

| Option | Default | Redisson |
|---|---|---|
| `.writer_retry_attempts(n)` | 1: the writer is called at most `n` times for one change | `writerRetryAttempts` (Redisson's `0` is one call) |
| `.writer_retry_interval(d)` | 100 ms between two calls | `writerRetryInterval` |

`writer_retry_attempts(0)` is an `Error::Config` at `build()`. Each failed attempt but the last is logged at `warn` with the map name.
