---
title: Limitations
description: Things to know about this version.
---

- **Redis 6.2 or newer** is needed for `Bucket::get_set` and `Bucket::get_del`.
- **Subscriptions are kept.** When a program waits for a lock name, it stays subscribed to that name until the client is dropped. If you wait on a huge number of different lock names, the list of subscriptions grows.
- **Lost messages.** After a lost connection, a waiting program may miss the "unlocked" message. It then wakes up when the lease ends.
- **Dropping a guard without a runtime.** The lock cannot be released at once. It frees itself when the lease ends.
- **Redis Cluster.** `rename` can fail when the old and new names are in different hash slots. Redis itself does this.
- **Numbers.** `Map::incr_by` needs values that the codec writes as plain numbers.
- **Short times.** Time limits and leases are rounded up to whole milliseconds. Zero is an error.
- **Before 1.0**, the API can change between minor versions.
