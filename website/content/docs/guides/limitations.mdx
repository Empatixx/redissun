---
title: Limitations
description: Things to know about this version.
---

- **Redis 6.2 or newer** is needed for `Bucket::replace` and `Bucket::take`.
- **Semaphore permits have no owner.** If a program crashes while it holds permits, they are lost until someone adds them back. Use `PermitExpirableSemaphore` with a lease when that matters.
- **Lost messages.** After a lost connection, a waiting program may miss the "unlocked" message. It then wakes up when the lease ends.
- **Dropping a guard without a runtime.** The lock cannot be released at once. It frees itself when the lease ends.
- **Redis Cluster.** `rename` can fail when the old and new names are in different hash slots. Redis itself does this.
- **RateLimiter.** `rename` is not supported. There is no `keepAliveTime` yet. With `RateType::PerClient`, every client instance leaves two small keys behind. Call `expire` on the limiter to let them go away.
- **Numbers.** `HashMap::incr_by` needs values that the codec writes as plain numbers.
- **HashMap and Redisson's `RMap`.** There is no `mapReduce` (redissun has no executor service) and no `TrackingListener` (redissun does not use RESP3 client tracking). `loadAll` comes with map loaders. `keys_with` and the other pattern scans read the whole hash, while Redisson's `readAllKeySet(pattern)` reads only the first `HSCAN` page. Map events of different kinds can arrive out of order among themselves, and without subkey notifications (Redis 8.8 with `T`) a field event comes 50 ms after its write and without the key.
- **Equal values.** `Vec`, `VecDeque` and `HashSet` compare values by their encoded bytes. The codec must give the same bytes for equal values. The JSON codec does this for structs and numbers, but not for a `HashMap` inside a value, because its key order is random.
- **Collections.** `Vec::insert` and `Vec::remove` by index are O(n). Iteration reads pages, so changes made while you read can make you miss a value or see it twice.
- **Blocking pops** use their own short-lived connection. A pop that is dropped while an element is on its way can lose that element. Use `.timeout(wait)` for time limits.
- **Topic** does not store messages. A slow subscriber that falls more than 256 messages behind gets `Error::Lagged`. Use `ReliableTopic` when every message must arrive.
- **RwLock** does not prefer writers, and a reader cannot be upgraded to a writer.
- **FairLock** keeps a place in the queue for about 5 seconds per waiter ahead of it. A waiter that crashed is skipped after that. A waiter that is cancelled at the very moment its first attempt runs can leave a stale place that also ends after that time.
- **HashMapCache** background clean-up runs on the runtime that first created the cache.
- **Short times.** Time limits and leases are rounded up to whole milliseconds. Zero is an error.
- **Before 1.0**, the API can change between minor versions.
