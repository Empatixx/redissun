---
title: SetMultimap
description: A map whose keys each hold a set of values, Redisson's RSetMultimap. Experimental.
---

**Experimental.** A `SetMultimap` maps each key to a set of values. A key holds each value at most once; values are equal when their encoded bytes are equal. It is Redisson's `RSetMultimap`, with the same data in Redis, so Java and Rust clients share it.

```rust
let tags = client.set_multimap::<String, String>("tags");

tags.insert("post-1", "rust").await?;
tags.insert("post-1", "redis").await?;
let all = tags.get_all("post-1").await?; // "rust" and "redis", in no particular order
```

## Methods

| Method | Redisson | Notes |
|---|---|---|
| `insert(&k, &v)` | `put` | adds the value; `true` when it was new for the key |
| `get_all(&k)` | `getAll` | the values in no particular order (a `Vec`), empty for a missing key |
| `contains_key(&k)` | `containsKey` | whether the key has any values |
| `len()` | `size` | the values under all keys |
| `key_len()` | `keySize` | the keys (`HLEN`) |
| `is_empty()` | `isEmpty` | `len() == 0` |
| `extend(&k, values)` | `putAll(key, values)` | `true` when any value was new |
| `remove(&k, &v)` | `remove(key, value)` | the key goes with its last value |
| `remove_all(&k)` | `removeAll` | removes the key and returns its values |
| `replace_values(&k, values)` | `replaceValues` | returns the old values |
| `set_values(&k, values)` | `fastReplaceValues` | replaces without reading the old values |
| `remove_many(&[&k, ..])` | `fastRemove` | how many of the keys were there |
| `remove_from_all_keys(&[&v, ..])` | `fastRemoveValue` | removes each value from every key, and a key it empties; how many were removed |
| `contains_value(&v)`, `contains_entry(&k, &v)` | `containsValue`, `containsEntry` | |
| `keys_to_vec()` | `readAllKeySet` | every key (`HKEYS`) |
| `clear()` | `clear`, `delete` | deletes the hash and every set |
| `lock(&k)`, `fair_lock(&k)`, `rw_lock(&k)`, `semaphore(&k)`, `count_down_latch(&k)`, `permit_expirable_semaphore(&k)` | `getLock(key)`, … | the objects Redisson keeps per key, under the same names |

## Empty inputs

`extend(&k, [])` sends nothing and returns `false`, so no key is left without values (Redisson's script would add the key to the hash). `replace_values(&k, [])` and `set_values(&k, [])` remove the key, the first returning its old values. `remove_many(&[])` and `remove_from_all_keys(&[])` send nothing and return `0`.

## Streams

| Method | Redisson | Yields |
|---|---|---|
| `iter()`, `iter_paged(n)` | `entries()`, `entries(count)` | every `(key, value)` pair |
| `keys()`, `keys_paged(n)` | `keySet()`, `keySet(count)` | every key |
| `values()`, `values_paged(n)` | `values()`, `values(count)` | every value of every key |

```rust
use futures::TryStreamExt;

let pairs: Vec<(String, String)> = tags.iter().try_collect().await?;
```

The keys are read with `HSCAN … COUNT n`, `n` being the page size (10 by default, as in Redisson; `0` means 10). The values of each key are read with `SSCAN … COUNT n`. Keys without values yield nothing in `iter` and `values`. Like every scan, a stream may miss or repeat entries that change while it runs.

## Values of one key

`get(&k)` returns a `SetMultimapValues` handle on the set of the key, Redisson's `get(key)`. It is lazy: building it sends nothing, and each method is one request.

```rust
let post = tags.get("post-1")?;
post.insert("tokio").await?;
let has_both = post.contains_all(&["rust", "tokio"]).await?;
```

| Method | Redisson | Through |
|---|---|---|
| `insert(&v)`, `extend(values)` | `add`, `addAll` | the multimap's `insert`/`extend`, so a new key joins the hash; `extend` returns how many values were new |
| `remove(&v)`, `remove_values(&[&v, ..])` | `remove`, `removeAll` | the multimap scripts; the key goes with its last value |
| `clear()` | `delete` | `remove_many` of the key |
| `contains(&v)`, `contains_all(&[&v, ..])`, `len()`, `is_empty()`, `to_vec()`, `iter()` | `contains`, `containsAll`, `size`, `isEmpty`, `readAll`, `iterator` | reads of the set |
| `retain(&[&v, ..])` | `retainAll` | writes to the set only |

`as_set()` returns the raw [`HashSet`](./hash-set) on the values key for the rest of `RSet` (set algebra, `pop`, `random`, `move_to`, …). Writes through it do not add the key to the multimap, as with Redisson's inherited `RSet` methods. `name()` is the name of the set.

`retain` and writes through `as_set()` do not touch the hash, as in Redisson. When one empties the set, `contains_key` is `false`, `get_all` is empty and the streams skip the key, but `key_len` and `keys` count it until `remove_all` or `remove_many`.

## Events

`events()` listens to every change, `events_of(&[MultimapEventKind::ValueAdded, ..])` to some. Both return a `MultimapEvents`; `recv()` waits for the next `MultimapEvent`, `into_stream()` turns it into a stream, and dropping it stops listening (Redisson's `removeListener`).

| Event | Redis event | Redisson listener |
|---|---|---|
| `Put { key }` | `hset` on the hash (a new key) | `MapPutListener` |
| `Removed { key }` | `hdel` on the hash (a key went) | `MapRemoveListener` |
| `ValueAdded { name }` | `sadd` on a set of the multimap | `SetAddListener` |
| `ValueRemoved { name }` | `srem` on a set of the multimap | `SetRemoveListener` |
| `Deleted` | `del` of the hash | `DeletedObjectListener` |
| `Expired` | `expired` of the hash | `ExpiredObjectListener` |

```rust
let mut events = tags.events().await?;
tags.insert("post-1", "rust").await?;
let event = events.recv().await?; // Put or ValueAdded, in either order
```

Redis sends these only when `notify-keyspace-events` enables them, as for Redisson: `E` with `h` for `Put` and `Removed`, `s` for the value events, `g` for `Deleted`, `x` for `Expired`. `key` is `Some` only with `T` (Redis 8.8 or newer), otherwise `None`, as Redisson's listeners get `null`. `name` is the set's name, `{name}:<hash>`; value events of other keys are dropped by that prefix, as in Redisson. Events of different kinds come from different subscriptions and may arrive in another order than the writes. In a cluster the listener hears the node of the client's pub/sub connection.

## Object methods

The `Object` methods cover the hash and the set of every key, with Redisson's scripts:

| Method | Redisson | Notes |
|---|---|---|
| `del()` | `delete` | deletes the hash and every set; `true` when anything was deleted |
| `expire(ttl)` | `expire` | sets the TTL on the hash and every set |
| `persist()` | `clearExpire` | clears the TTL of every set; returns whether the hash had one |
| `rename(new)` | `rename` | renames the hash and every set; fails when the multimap does not exist |
| `exists()`, `ttl()` | `isExists`, `remainTimeToLive` | read the hash |

The scripts name the sets from the hash, so in a cluster `rename` works only to a name in the same slot, for example `{t}:a` to `{t}:b`.

## How it is stored

Redisson's layout:

- A hash at the name maps each encoded key to `Hash.hash128toBase64` of the encoded key (a 22-character string, stored as is, not encoded). With `JsonCodec` the key `"key"` maps to `IKm9EBQhlzpVIBxUXDHBWw`.
- The values of a key live in the set `{name}:<hash>`, or `name:<hash>` when the name already has a `{`. So every key of the multimap is in the slot of the name, also in a cluster.
