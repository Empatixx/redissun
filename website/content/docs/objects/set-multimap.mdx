---
title: SetMultimap
description: A map whose keys each hold a set of values, Redisson's RSetMultimap. Experimental.
---

**Experimental.** A `SetMultimap` maps each key to a set of values. A key holds each value at most once; values are equal when their encoded bytes are equal. It is Redisson's `RSetMultimap`, with the same data in Redis, so Java and Rust clients share it.

```rust
let tags = client.set_multimap::<String, String>("tags");

tags.insert("post-1", "rust").await?;
tags.insert("post-1", "redis").await?;
let all = tags.get_all("post-1").await?; // "rust" and "redis", in no particular order
```

## Methods

| Method | Redisson | Notes |
|---|---|---|
| `insert(&k, &v)` | `put` | adds the value; `true` when it was new for the key |
| `get_all(&k)` | `getAll` | the values in no particular order (a `Vec`), empty for a missing key |
| `contains_key(&k)` | `containsKey` | whether the key has any values |
| `len()` | `size` | the values under all keys |
| `key_len()` | `keySize` | the keys (`HLEN`) |
| `is_empty()` | `isEmpty` | `len() == 0` |
| `extend(&k, values)` | `putAll(key, values)` | `true` when any value was new |
| `remove(&k, &v)` | `remove(key, value)` | the key goes with its last value |
| `remove_all(&k)` | `removeAll` | removes the key and returns its values |
| `replace_values(&k, values)` | `replaceValues` | returns the old values |
| `set_values(&k, values)` | `fastReplaceValues` | replaces without reading the old values |
| `remove_many(&[&k, ..])` | `fastRemove` | how many of the keys were there |
| `remove_from_all_keys(&[&v, ..])` | `fastRemoveValue` | removes each value from every key, and a key it empties; how many were removed |
| `contains_value(&v)`, `contains_entry(&k, &v)` | `containsValue`, `containsEntry` | |
| `keys_to_vec()` | `readAllKeySet` | every key (`HKEYS`) |
| `clear()` | `clear`, `delete` | deletes the hash and every set |
| `lock(&k)`, `fair_lock(&k)`, `rw_lock(&k)`, `semaphore(&k)`, `count_down_latch(&k)`, `permit_expirable_semaphore(&k)` | `getLock(key)`, … | the objects Redisson keeps per key, under the same names |

## Empty inputs

`extend(&k, [])` sends nothing and returns `false`, so no key is left without values (Redisson's script would add the key to the hash). `replace_values(&k, [])` and `set_values(&k, [])` remove the key, the first returning its old values. `remove_many(&[])` and `remove_from_all_keys(&[])` send nothing and return `0`.

## Object methods

The `Object` methods cover the hash and the set of every key, with Redisson's scripts:

| Method | Redisson | Notes |
|---|---|---|
| `del()` | `delete` | deletes the hash and every set; `true` when anything was deleted |
| `expire(ttl)` | `expire` | sets the TTL on the hash and every set |
| `persist()` | `clearExpire` | clears the TTL of every set; returns whether the hash had one |
| `rename(new)` | `rename` | renames the hash and every set; fails when the multimap does not exist |
| `exists()`, `ttl()` | `isExists`, `remainTimeToLive` | read the hash |

The scripts name the sets from the hash, so in a cluster `rename` works only to a name in the same slot, for example `{t}:a` to `{t}:b`.

## How it is stored

Redisson's layout:

- A hash at the name maps each encoded key to `Hash.hash128toBase64` of the encoded key (a 22-character string, stored as is, not encoded). With `JsonCodec` the key `"key"` maps to `IKm9EBQhlzpVIBxUXDHBWw`.
- The values of a key live in the set `{name}:<hash>`, or `name:<hash>` when the name already has a `{`. So every key of the multimap is in the slot of the name, also in a cluster.
