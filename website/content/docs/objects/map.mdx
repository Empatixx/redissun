---
title: Map
description: A shared map that works like HashMap.
---

A `Map` keeps its entries in a Redis hash. Keys and values both go through the codec.

```rust
let users = client.map::<String, User>("users");

users.insert("jirka".into(), user).await?;
let found = users.get("jirka").await?;
```

Lookups take a borrowed key, like `HashMap::get`. So `users.get("jirka")` does not need a new `String`.

## Methods

| Method | Redis command | Notes |
|---|---|---|
| `insert(k, v)` | Lua script | returns the old value |
| `get(&k)` | `HGET` | |
| `remove(&k)` | Lua script | returns the removed value |
| `contains_key(&k)` | `HEXISTS` | |
| `len()` and `is_empty()` | `HLEN` | |
| `clear()` | `DEL` | |
| `extend(entries)` | `HSET` | one request. An empty list does nothing. |
| `get_many(&[&k])` | `HMGET` | same order as the keys |
| `insert_nx(k, v)` | `HSETNX` | `true` if the entry was added |
| `incr_by(&k, delta)` | `HINCRBY` | a missing entry starts at zero |
| `incr_by_float(&k, delta)` | `HINCRBYFLOAT` | |

`incr_by` and `incr_by_float` need values that the codec writes as plain numbers. Integers and floats do this with the JSON codec.

## Read all entries

`iter`, `keys` and `values` return a `Stream`. They use `HSCAN` and read 100 entries at a time. The whole map is never loaded at once.

```rust
use futures::TryStreamExt;

let entries: Vec<(String, User)> = users.iter().try_collect().await?;
```

## Missing keys and null values

`get` returns `None` for a missing key. If your value type is an `Option`, a stored `None` comes back as `Some(None)`. So you can tell the two cases apart.
