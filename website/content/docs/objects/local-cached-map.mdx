---
title: LocalCachedMap
description: A HashMap with a cache inside your program.
---

A `LocalCachedMap` is a `HashMap` that keeps the entries it has read in your program's memory. A read that hits the cache needs no network round trip. When another instance changes an entry, your copy is dropped or updated.

```rust
use redissun::EvictionPolicy;

let users = client
    .local_cached_map::<String, String>("users")
    .eviction_policy(EvictionPolicy::Lru)
    .cache_size(10_000)
    .ttl(Duration::from_secs(300))
    .build()
    .await?;

users.insert("jirka", "Jirka").await?;
let name = users.get("jirka").await?;
```

## Options

The defaults are Redisson's `LocalCachedMapOptions` defaults.

| Option | Notes |
|---|---|
| `eviction_policy(..)` | which local entry to drop when the cache is full: `None` (default, no limit), `Lru` or `Lfu`. Redisson's `SOFT` and `WEAK` have no Rust counterpart. |
| `cache_size(n)` | keep at most `n` entries locally. 0, the default, means no limit. Ignored with `EvictionPolicy::None`, as in Redisson. |
| `ttl(time)` | drop a local entry this long after it was stored |
| `max_idle(time)` | drop a local entry that was not read for this long |
| `sync_strategy(..)` | `Invalidate` (default): other instances drop the entry. `Update`: they receive the new value. `None`: nothing is sent. |
| `reconnection_strategy(..)` | what happens after the pub/sub connection comes back: `None` (default) keeps the cache, `Clear` empties it, `Load` drops the keys changed meanwhile, read from a 10 minute log in Redis, or everything when the instance was away longer |
| `store_cache_miss(bool)` | also cache that a key is missing. Off by default. |

## Methods

| Method | Notes |
|---|---|
| `get(&k)` | local cache first, then Redis. A value read from Redis is cached. |
| `insert(&k, &v)` | caches the new value, writes to Redis, returns the previous value and tells the others |
| `remove(&k)` | removes and tells the others when the key existed |
| `contains_key(&k)` | a cached key answers without a round trip |
| `len()`, `is_empty()` | ask Redis |
| `clear()` | empties the map for everybody; returns whether there was anything to remove, and tells the others only then |
| `local_len()`, `cached_entries()`, `clear_local()` | the local cache of this instance only |
| `clear_local_everywhere()` | empties the local cache of every instance without changing Redis, like Redisson's `clearLocalCache` (it does not wait for the others) |
| `iter()`, `keys()`, `values()` | stream from Redis and do not use the cache |

## What it guarantees

- A write and its message are sent in one Lua script, as in Redisson. A removal or `clear()` that changed nothing sends nothing.
- An instance does not react to its own messages.
- If a read was running while a change of the same key arrived, the stale value is not cached.
- When this client falls behind on the messages, the whole local cache is cleared. A lost pub/sub connection is handled by the reconnection strategy; with the default `None`, changes made meanwhile are missed until the entry changes again or expires locally.
- A message can arrive a few milliseconds after the write, so another instance may read the old value for a short time.

Only changes made through a `LocalCachedMap` are announced. A plain `HashMap` of the same name, or `del()`, changes Redis without telling the others. Their cached entries stay until they expire (`ttl`, `max_idle`), are pushed out, or you call `clear()`.

The data in Redis is a normal hash, so a `HashMap` with the same name and codec reads the same entries.
