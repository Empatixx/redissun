---
title: AtomicF64
description: A shared decimal number.
---

An `AtomicF64` is an `f64` in a Redis string. A missing number reads as 0.

```rust
let total = client.atomic_f64("total");

total.add(2.5).await?;
let now = total.get().await?;
```

## Methods

Every method is `async` and returns `redissun::Result<T>`. The **Returns** column shows `T`.

| Method | Redis command | Returns |
|---|---|---|
| `get()` | `GET` | the value, 0 if missing |
| `set(v)` | `SET` | `()` |
| `swap(v)` | `GETSET` | the old value |
| `take()` | Lua script | the old value |
| `compare_and_set(expected, update)` | Lua script | `true` if the value was changed |
| `compare_and_delete(comparison, threshold)` | Lua script | `true` if the number was deleted |
| `set_if_less(less, v)` and `set_if_greater(greater, v)` | Lua script | `true` if the value was changed |
| `add(delta)` | `INCRBYFLOAT` | the new value |
| `fetch_add(delta)` | `INCRBYFLOAT` | the value before; `fetch_add(1.0)` is Redisson's `getAndIncrement` |
| `incr()` and `decr()` | `INCRBYFLOAT` | the new value |

`compare_and_set`, `set_if_less` and `set_if_greater` treat a missing number as 0, like Redisson. `compare_and_delete` takes a `Comparison` (`Less`, `LessOrEqual`, `Greater`, `GreaterOrEqual`, `Equal` or `NotEqual`) and never deletes a missing number.

The value is stored as a plain number, not through the codec. Redis refuses `NaN` and infinity, so those calls return an error.
