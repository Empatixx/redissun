---
title: HashSetCache
description: A set whose values expire.
---

A `HashSetCache` is a set in which every value can have its own time to live. It is the set version of `HashMapCache`.

```rust
let seen = client.hash_set_cache::<String>("seen");

seen.insert("request-1").ttl(Duration::from_secs(60)).await?;
let again = seen.contains("request-1").await?;
```

## Methods

| Method | Notes |
|---|---|
| `insert(&v)` | returns `true` when the value was new or expired. Add `.ttl(time)` to make it expire (zero means never); a new insert replaces the old time limit. |
| `insert_nx(&v)` | adds only when there is no live value and keeps the time limit of a live one, like Redisson's `tryAdd`. Takes `.ttl(time)` too. |
| `contains(&v)` | live values only |
| `remove(&v)` | returns `true` when the value was stored, even if it had expired, as in Redisson |
| `entry_ttl(&v)` | time left. `None` means no limit or not in the set. |
| `len()`, `is_empty()`, `clear()` | `len` counts live values |
| `evict_expired()` | deletes expired values now and returns how many |
| `expired()` | listens to the values the clean-up deletes, like Redisson's `SetExpiredListener` |
| `iter()` | a stream of the live values |

Time comes from the Redis server, so clients with different clocks agree. Expired values are hidden at once. A background task deletes them in the same way as for `HashMapCache`: up to 100 per run, with Redisson's pacing between `eviction_interval` and 30 minutes and a lock so one client cleans per run. It publishes every deleted value on `redissun_set_cache_expired:{name}`.

## Redis keys

One sorted set `{name}`. The score of each value is its expiry time in milliseconds. A value without a limit gets the score `92233720368547758 - now`, as in Redisson's `RedissonSetCache`.
