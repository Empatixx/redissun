---
title: DelayedQueue
description: Values that arrive in a queue after a delay.
---

A `DelayedQueue` holds values back and releases them into a destination `VecDeque` after a delay. Consumers read from the destination.

```rust
let jobs = client.vec_deque::<String>("jobs");
let delayed = client.delayed_queue(&jobs);

delayed.push("send-email", Duration::from_secs(60)).await?;

let job = jobs.pop_front_wait().await?;
```

## Methods

| Method | Notes |
|---|---|
| `push(&v, delay)` | the value reaches the destination after `delay`, like Redisson's `offer`. It is sent once and not retried. |
| `remove(&v)`, `remove_all(&[..])`, `retain_all(&[..])` | take waiting values out |
| `contains(&v)`, `contains_all(&[..])` | look at the waiting values |
| `peek()`, `poll()`, `poll_many(n)` | read or take the waiting values in push order, before their delay ends |
| `poll_last_and_offer_first_to(&deque)` | moves the last waiting value to the front of another `VecDeque` |
| `len()`, `is_empty()` | waiting values only |
| `values()` | the waiting values in push order |
| `clear()` | drops the waiting values |

Equal values are kept as separate entries. `DelayedQueue` also has the `Object` methods, which apply to the waiting values.

## How it works

This follows Redisson's `RedissonDelayedQueue`. Waiting values live in a list and in a sorted set by due time, in the same format as in Redisson, with an 8 byte random id in front. The due time comes from the clock of the client that pushes, as in Redisson.

Each client that holds a `DelayedQueue` for a destination runs one background task that moves due values to the end of the destination, like Redisson's `QueueTransferTask`. A value that becomes the earliest one is announced through pub/sub with its due time, and the task sleeps until then. The task also looks right after it subscribes and after a reconnect, retries after 5 seconds when Redis fails, and as a fallback looks every minute.

The task stops when the last `DelayedQueue` for the destination in the client is dropped. Keep one alive in at least one program, or the values will stay until one is.
