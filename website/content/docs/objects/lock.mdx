---
title: Lock
description: A shared lock that its owner can take again.
---

`Lock` is like Redisson's `RLock`. Its methods are like `tokio::sync::Mutex`.

```rust
let lock = client.lock("order:42");

let guard = lock.lock().await?;
guard.unlock().await?;
```

## Taking the lock

| Method | What it does |
|---|---|
| `lock()` | waits until the lock is free |
| `try_lock()` | returns `None` at once if the lock is taken |
| `lock_for(wait)` | returns `None` if `wait` runs out |
| `lock_with(options)` | lets you set both wait time and lease |

```rust
use redgrid::LockOptions;
use std::time::Duration;

let options = LockOptions::new().wait(Duration::from_secs(2)).lease(Duration::from_secs(10));
let guard = lock.lock_with(options).await?;
```

A lease must be longer than zero. Very small leases are rounded up to one millisecond.

## Releasing the lock

Call `guard.unlock().await`. You get the result, and you see errors. If the lease already ended, you get `Error::LockNotHeld`.

If you drop the guard, the lock is also released in the background. The explicit call is better.

## Taking the lock again

The owner can take the lock many times. Each `lock` needs its own `unlock`. `hold_count()` shows how many are open.

The owner is the client plus the current tokio task. Two tasks that share one `Client` are two different owners, and they block each other.

Code outside any spawned task (the body of `#[tokio::main]`, `block_on`, `spawn_blocking`) shares one owner per client. Futures joined with `join!` inside one task also share that task's owner. In these cases the lock does not block. If you need real blocking, give each piece of work its own `tokio::spawn`.

## Cancelling a wait

If you drop a `lock()` future that is still waiting, for example with `tokio::time::timeout`, the lock can stay taken until its lease ends. This happens only if the server had already given you the lock. For a time limit, use `lock_for(wait)`.

## Lease and watchdog

If you give no lease, the lock uses the client's `lock_lease` (30 seconds by default). While you hold the guard, a watchdog renews the lease every third of that time. If your program crashes, the renewing stops and the lock frees itself.

If you give a lease, there is no watchdog. The lock ends when the lease ends.

## Waiting without polling

Waiting programs listen on a Redis channel. They wake up as soon as the lock is released. If a message is lost, they wake up when the current lease would end.

## Questions about the lock

| Method | Meaning |
|---|---|
| `is_locked()` | someone holds the lock |
| `is_held_by_current()` | the current task holds the lock |
| `hold_count()` | how many times the current task took it |
| `force_unlock()` | releases the lock, whoever owns it |
