---
title: VecDeque
description: A shared queue that works like VecDeque.
---

A `VecDeque` keeps its values in a Redis list. You can add and remove at both ends, so it works as a queue (first in, first out) or as a stack (last in, first out).

```rust
let jobs = client.vec_deque::<String>("jobs");

jobs.push_back("send-email").await?;
let next = jobs.pop_front().await?;
```

Every pop is one atomic Redis command. If many programs pop from the same deque, each value goes to exactly one of them.

## Methods

| Method | Redis command | Notes |
|---|---|---|
| `push_back(&v)` | `RPUSH` | |
| `push_front(&v)` | `LPUSH` | |
| `pop_back()` | `RPOP` | returns `None` when empty |
| `pop_front()` | `LPOP` | returns `None` when empty |
| `extend_back(values)`, `extend_front(values)` | `RPUSH`, `LPUSH` | return the new length. Add `.if_exists()` to push only onto an existing deque (`RPUSHX`, `LPUSHX`). |
| `pop_front_many(n)`, `pop_back_many(n)` | Lua script | up to `n` values, atomically |
| `remove_value(&v)`, `remove_last_value(&v)` | `LREM` | removes the equal value nearest the front or the back |
| `to_vec()`, `drain()` | `LRANGE`, Lua script | all values; `drain` also empties the deque |
| `pop_back_push_front(&to)` | `RPOPLPUSH` | moves the back value to the front of `to` and returns it. `to` may be this deque. |
| `pop_front_push_back(&to)` | `LMOVE LEFT RIGHT` | moves the front value to the back of `to` and returns it |
| `front()` and `back()` | `LINDEX` | read without removing |
| `contains(&v)`, `position(&v)` | `LPOS` | the first equal value, counted from the front |
| `len()` and `is_empty()` | `LLEN` | |
| `clear()` | `DEL` | |
| `iter()`, `iter_rev()` | `LRANGE` | a stream from front to back, or from back to front, 100 values at a time |
| `pop_front_wait()`, `pop_back_wait()` | `BLPOP`, `BRPOP` | wait for a value. Add `.timeout(wait)` to get `None` when `wait` runs out. |
| `pop_front_wait_any(&[&other])`, `pop_back_wait_any(&[&other])` | `BLPOP`, `BRPOP` | wait for a value in this deque or one of the others; gives the name of the deque and the value |
| `pop_back_push_front_wait(&to)`, `pop_front_push_back_wait(&to)` | `BRPOPLPUSH`, `BLMOVE` | like the moves above, but wait for a value |

`pop_front` and `pop_back` return `None` at once when the deque is empty.

## Wait for work

The blocking pops turn a deque into a work queue. A worker waits, and a producer pushes.

```rust
let jobs = client.vec_deque::<String>("jobs");

loop {
    if let Some(job) = jobs.pop_front_wait().timeout(Duration::from_secs(5)).await? {
        handle(job).await;
    }
}
```

A blocking pop first tries a normal pop. Only when the deque is empty does it open its own short-lived connection and block on that. So a waiting worker never slows down your other calls. Each element goes to exactly one worker.

Use `.timeout(wait)` for a time limit. As in Redisson, it is rounded down to whole seconds, and a timeout under one second waits one second. A zero timeout pops once and does not wait. In Redis Cluster the deques of `pop_front_wait_any` and `pop_back_wait_any` must share a hash slot. Do not wrap a pop in `tokio::time::timeout`: if the future is dropped at the wrong moment, an element that Redis has just handed over is lost.

## Same list as Vec

`VecDeque` and `Vec` use the same kind of Redis list. If you open both with the same name, they see the same data.
