---
title: Introduction
description: Shared objects on Redis for Rust, inspired by Redisson.
---

redissun gives you objects that live in Redis. You use them like normal Rust objects. Every program that uses the same name sees the same data.

## What you get

| Object | Stored in Redis as | Redisson name |
|---|---|---|
| `Bucket` | string | `RBucket` |
| `HashMap` | hash | `RMap` |
| `Vec` | list | `RList` |
| `VecDeque` | list | `RDeque` |
| `HashSet` | set | `RSet` |
| `LocalCachedMap` | hash and pub/sub | `RLocalCachedMap` |
| `Lock` | hash and pub/sub | `RLock` |
| `RwLock` | hash, set, strings and pub/sub | `RReadWriteLock` |
| `FairLock` | hash, list, sorted set and pub/sub | `RFairLock` |
| `SortedSet` | sorted set | `RScoredSortedSet`, `RPriorityQueue` |
| `FencedLock` | hash, string and pub/sub | `RFencedLock` |
| `MultiLock` | the locks it holds | `RedissonMultiLock` |
| `DelayedQueue` | list, sorted set and pub/sub | `RDelayedQueue` |
| `BitSet` | string | `RBitSet` |
| `HyperLogLog` | HyperLogLog | `RHyperLogLog` |
| `BloomFilter` | string and hash | `RBloomFilter` |
| `HashMapCache` | hash and sorted set | `RMapCache` |
| `HashSetCache` | sorted set | `RSetCache` |
| `Topic` | pub/sub | `RTopic` |
| `Stream` | stream | `RStream` |
| `Geo` | sorted set | `RGeo` |
| `AtomicI64` | string | `RAtomicLong` |
| `Semaphore` | string and pub/sub | `RSemaphore` |
| `CountDownLatch` | string and pub/sub | `RCountDownLatch` |
| `RateLimiter` | hash, string and sorted set | `RRateLimiter` |

- It uses tokio. Every call is `async`.
- Values are turned into bytes by a codec. The default is JSON.
- Anything that must be atomic runs as a Lua script.
- `Lock` can be taken again by its owner, a watchdog keeps it alive, and waiting programs wake up without polling.
- Method names follow `std` and `tokio` when they have the same method. Otherwise they follow the Redis command name.

## Requirements

Redis or Valkey 6.2 or newer.
