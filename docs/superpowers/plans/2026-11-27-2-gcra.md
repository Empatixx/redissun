# 2: Gcra (Redisson `RGcra`) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A new, experimental `Gcra` rate limiter (Generic Cell Rate Algorithm) with every non-deprecated method of Redisson 4.8.0's `RGcra` (`javap org.redisson.api.RGcra`: `trySetRate`, `setRate`, `getConfig`, `tryAcquire()`, `tryAcquire(long)`, plus the two deprecated `tryAcquire(maxBurst, rate, period[, tokens])`). It uses Redisson's config hash and scripts, so it shares data with Redisson. It sends the server's `GCRA` command when the server has it, as Redisson does, and on every other server (all released Redis and Valkey versions) it runs a Lua port of Redis's own `gcra.c`, which gives the same replies.

**Architecture:** One file, `src/coordination/gcra.rs`, next to `rate_limiter.rs`. `Gcra { key: Key }` lives at the raw name (the GCRA state, Redisson's `getRawName()`), with one companion key `{name}:config` (a hash with `maxBurst`, `rate`, `period`). The config methods run Redisson's three scripts verbatim. `try_acquire()` returns an `IntoFuture` builder with `.tokens(n)`. It first asks a per-client probe whether the server has `GCRA`. If it does, the builder runs Redisson's `tryAcquire` script verbatim (it calls `redis.call('GCRA', ...)`). If not, it runs `TRY_ACQUIRE_LUA`: Redisson's config-reading prefix followed by a line-by-line Lua port of `gcraCommand` from `redis/src/gcra.c`. Both paths return the native reply, the five integers, which become a `GcraResult` with `Duration`s and an `Option`.

**Tech Stack:** Rust 2024, tokio, redis-rs, testcontainers. Servers: Redis 7.4 (Lua path), `redis:8.8-m03-alpine` (native `GCRA`, the only published image that has it), Redis 6.2 (the crate's minimum), and a 7.4 Cluster and an 8.8-m03 Cluster.

**Spec:** `docs/superpowers/specs/2026-11-26-redisson-4x-objects-design.md` (section "### 2. `Gcra`", "API conventions", "Constraints", "Testing", "Risks") and `docs/superpowers/specs/2026-11-27-rust-idiomatic-api.md`, whose naming rules replace the spec's naming lines (`try_set_rate` → `init_rate`, rule 3).

**Branch:** `feat/gcra`, from `main` after `feat/map-cache-native` (#1) is merged.

## The server command: what was found (2026-11-27)

- **What Redisson sends.** `tryAcquire()`/`tryAcquire(n)` run `EVAL` with KEYS `[{name}:config, name]` and ARGV `[tokens]`. The script reads the three config fields, `assert`s them (`'GCRA rate is not set'`), and calls `redis.call('GCRA', KEYS[2], maxBurst, rate, period)`, adding `'TOKENS', ARGV[1]` when `tokens ≠ 1` (`RedissonGcra.java` 131–146). The deprecated overloads send the bare `GCRA name maxBurst rate period [TOKENS n]` command (167–181). `RedisCommands.NO_RETRY` lists `GCRA`. Redisson has **no Lua fallback**: on a server without the command, the script fails with "Unknown Redis command called from script".
- **The command is Redis core, compiled out of every release.** `redis/redis` has `src/gcra.c` (added in #14826 on 2026-03-18, args renamed in #14950, its own object type `OBJ_GCRA` (`TYPE` = `gcra`, RDB type 36) in #14905). Then **#15191 "Hold GCRA out of the release" (2026-05-14)** wrapped all of it in `#ifdef ENABLE_GCRA`: "It was internally decided not to introduce GCRA into the new release … no decision is made on whether it will be kept". 8.8.0 GA (2026-05-25) and later do not have it. Checked locally: `redis:8.8-alpine` (8.8.3), `8.10-alpine` (8.10.3), `8.12-alpine` (8.12.0) and `valkey/valkey:latest` (9.2.1) all reply `ERR unknown command 'GCRA'`.
- **Where it runs.** Only the milestone images `redis:8.8-m02` and `redis:8.8-m03` (and their `-alpine` variants) were built before the hold. Redisson's own `RedissonGcraTest` starts `redis:8.8-m03`. Checked locally on `redis:8.8-m03-alpine` (`redis_version` 8.7.226): `COMMAND INFO GCRA` → `gcra -5 write denyoom fast 1 1 1 @write @fast @ratelimit`. `GCRA k 2 4 1` → `[0, 3, 2, -1, 1]`. `TYPE k` → `gcra`. `PTTL k` → ~250. `GET k` → `WRONGTYPE`. Redis-cell's `CL.THROTTLE` uses a different name and arguments and is not this command. Dragonfly and KeyDB were not found to have it.
- **Semantics (from `gcra.c`, the reference for the Lua port).** State: the theoretical arrival time (TAT) in **microseconds**, server clock (`commandTimeSnapshot`), stored as an `OBJ_GCRA` with `PEXPIREAT tat/1000` set on each allowed request. `max_burst + 1` is the bucket size. Emission interval = `round(period·10⁶ / tokens_per_period)` µs (at least 1). The reply is `[limited 0|1, max_burst+1, remaining, retry_after_s (-1 when allowed, or when tokens > max_burst+1, which never succeeds), full_burst_after_s]`. Argument errors: `max_burst` ≥ 0, `tokens_per_period` ≥ 1, `0 < period < 1e12`, `TOKENS` ≥ 1, three overflow errors. For replication the command is rewritten to `GCRASETVALUE`.

## Owner decisions (from the spec, 2026-11-26)

1. **Native when present, Lua otherwise** (spec §2, "My call"): call `GCRA` like Redisson when the server has it, otherwise run the Lua algorithm with the native reply shape. Documented: the two paths' state formats differ, so one key must not be used by both.
2. **The deprecated `tryAcquire(maxBurst, rate, period[, tokens])` is not ported** (spec §2).
3. **Experimental** in the README, docs page and rustdoc (spec "Goals").

## Decisions (mine, by the rules: Redisson parity, Lua/Redis logic 1:1, Rust-idiomatic)

- **Names and shapes** (spec names replaced by the naming rules):

  | Spec name | Plan name | Why |
  |---|---|---|
  | `try_set_rate(GcraConfig)` | `init_rate(max_burst, tokens_per_period, period) -> Result<bool>` | rule 3 (`trySetX` → `init_*`), and the same shape as `RateLimiter::init_rate(type, rate, interval)`. A plain `async fn`, since there is no option to build |
  | `set_rate(GcraConfig)` | `set_rate(max_burst, tokens_per_period, period) -> Result<()>` | `RateLimiter::set_rate` |
  | `config() -> Option<GcraConfig>` | the same | `RateLimiter::config` |
  | `try_acquire()`, `try_acquire_n(tokens)` | `try_acquire()` → `TryAcquire` builder with `.tokens(n)`, resolving to `Result<GcraResult>` | "optional arguments go in a builder" (API conventions), and it matches the command's own optional `TOKENS`. It cannot be `try_acquire(n)` like `RateLimiter`, because `RGcra.tryAcquire()` has no argument |

  Positional `u64`s (not a `GcraConfig` argument) keep the call close to the rate limiter's and to Redisson's `trySetRate(maxBurst, tokensPerPeriod, period)`. `GcraConfig` is the output of `config()`, `#[non_exhaustive]` with pub fields like `RateLimiterConfig`.
- **Result type:**
  ```rust
  #[derive(Clone, Copy, Debug, PartialEq, Eq)]
  #[non_exhaustive]
  pub struct GcraResult {
      #[doc(alias = "isLimited")] pub limited: bool,
      #[doc(alias = "getMaxTokens")] pub max_tokens: u64,          // max_burst + 1
      #[doc(alias = "getAvailableTokens")] pub available_tokens: u64,
      #[doc(alias = "getRetryAfterSeconds")] pub retry_after: Option<Duration>,      // None: allowed, or limited and asking for more than max_tokens (never passes)
      #[doc(alias = "getFullBurstAfterSeconds")] pub full_burst_after: Duration,
  }
  ```
  The decoder takes exactly 5 integers. Anything else is `Error::Redis("unexpected GCRA reply: …")`, Redisson's `IllegalStateException`. Negative values become `None` (for `retry_after`) or `0` (for the others). Times are whole seconds, `Duration::from_secs`, rounded up by the server.
- **Validation before any call** (Redisson's `validate`/`validateTokens`, which throw `IllegalArgumentException`) gives `Error::Config` with Redisson's wording in Rust names: `"tokens_per_period must be positive"`, `"period must be positive"`, `"tokens must be positive"`. Also `"max_burst must be at most i64::MAX"` and `"tokens must be at most i64::MAX"`, since the server parses a `long` and `u64` already excludes negatives. `period ≥ 1e12 s` and the overflow combinations are left to the server (native) or to the Lua port, which returns the same error texts.
- **Period encoding is Redisson's `toSeconds`/`fromSeconds`**: decimal seconds with trailing zeros stripped (`1s` → `"1"`, `250ms` → `"0.25"`, `100s` → `"100"`, `1ns` → `"0.000000001"`). `config()` parses that back exactly into a `Duration` (at most 9 fraction digits). Anything else is `Error::Config("the GCRA settings are not valid")`, the same as `RateLimiter::config`. Private `fn period_arg(Duration) -> String` and `fn parse_period(&str) -> Option<Duration>`, unit-tested.
- **Probe: does the server have `GCRA`?** A new `Core` field, `pub(crate) gcra_command: tokio::sync::OnceCell<bool>`, is filled once per client by `GCRA <name> 0 1 1 TOKENS`, routed by the object's key. The server checks the arguments before it looks up the key, so the probe never writes: a server with the command answers `ERR Missing TOKENS value` (yes), a server without it `unknown command` (no). `NOPERM` (a prefix match) counts as no too, because `redis.call('GCRA')` inside Redisson's script would fail the same way. Every other error (a lost connection, `LOADING`, `TRYAGAIN`, `CLUSTERDOWN`, `MASTERDOWN`, ...) is returned and nothing is cached, so the next acquire asks again. No `COMMAND INFO`, following #1's ACL lesson (commit f200b3b).
  - **It caches both answers**, unlike `MapCacheNative`'s keep-only-a-yes. Here the no is the normal path, and a per-call re-probe would double every acquire's round trips. A client must also not switch state formats in the middle of its life. Restarting the client after a server upgrade picks up the command. Documented.
- **The Lua path stores its state at the same raw key**, as a plain string holding the TAT in µs, with `PXAT tat/1000`: the data `GCRASETVALUE` writes, except that it is a string and not an `OBJ_GCRA`. That way `del`/`expire`/`set_rate`'s `del KEYS[2]` cover it unchanged. When both paths touch the same key, the result is an error and never a wrong answer: native `GCRA` on a string, and `GET` in the Lua script on an `OBJ_GCRA`, both give `WRONGTYPE`. The state heals itself, since every state key expires at its TAT. The spec says "ms". I use µs so that the Lua replies equal the native ones bit for bit (`gcra.c` computes in µs). Reason recorded.
- **The Lua port is 1:1 with `gcra.c`**, with two recorded deviations that Lua 5.1 forces: the overflow bound is 2⁵³, the largest exact double, instead of `LLONG_MAX`, with the same error texts; and numbers are written with `string.format('%.0f', x)`, because `tostring(1.8e15)` gives `1.8e+15`. The time comes from `TIME` inside the script, so it is the server clock, the same as native, cut to whole milliseconds as `commandTimeSnapshot() * 1000` is. The settings are checked as `gcra.c` checks them (`getPositiveLongFromObjectOrReply` for `max_burst`, `getRangeLongFromObjectOrReply(1, LONG_MAX)` for `tokens_per_period`), with the same error texts. Scripts that call `TIME` and then write replicate their effects on Redis 6.2 and later.
- **Script names (`static`s, each with a `/// RedissonGcra.<method>` or `/// Port of gcraCommand` comment):** `TRY_SET_RATE` (78–86, KEYS `[config]`), `SET_RATE` (95–102, KEYS `[config, name]`), `TRY_ACQUIRE` (131–146, KEYS `[config, name]`, verbatim), `TRY_ACQUIRE_LUA` (Redisson's four prefix lines from `TRY_ACQUIRE` verbatim, then the port). `config()` sends `HGETALL {name}:config`, Redisson's `HGETALL` decoder: an empty hash gives `None`.
- **Retries:** `init_rate` uses `eval_once` (Redisson's `evalWriteNoRetryAsync`). Both acquire scripts also use `eval_once`, a deliberate difference from Redisson's `evalWriteAsync` for `tryAcquire`: a retried acquire whose first reply was lost would take its tokens twice (Redisson also lists `GCRA` in `NO_RETRY`). `set_rate` uses `eval` (`evalWriteAsync`). `config` is a read.
- **Routing:** every script's first key is `{name}:config`, as in Redisson, and `Core::eval` routes by the first key. `{name}:config` and `name` share a slot (for `x`, the tag of `{x}:config` is `x`; a name like `{t}:x` keeps its tag).
- **`Object` over both keys** (spec "API conventions": "over all its keys"), through `Key::{del_all, expire_all, persist_all, rename_all}` with companion `suffix_name(name, "config")`:
  - `del` deletes both, like Redisson's `deleteAsync`.
  - `expire` and `persist` act on both, like Redisson's overrides. The next allowed acquire resets the state key's TTL to its TAT, as the server does.
  - `exists` is `EXISTS name {name}:config` > 0. Redisson checks the raw name only, which is false between `trySetRate` and the first acquire.
  - `ttl` is the `PTTL` of `{name}:config`, the key whose TTL only the user sets. The state key's TTL is the algorithm's own.
  - `rename` moves both keys (`rename_all`). Redisson's `rename` moves only the raw key and leaves the config behind. In a cluster, the new name must hash to the same slot, as for every multi-key object.

  The README and limitations list these differences.
- **No codec:** everything is a string, as with Redisson's `StringCodec` and `RateLimiter`. `client.gcra(name)` has no type parameters. `getGcra(CommonOptions)` maps to `client.gcra(name)` plus the client's own timeouts.
- **Reference implementation for tests:** the spec asks for property tests against "a reference implementation in Rust". The server's own C code is a better reference than a second hand-written port, so the property test compares the Lua path (on 7.4) with the native command (on 8.8-m03) over generated sequences (Task 3). There is no extra Rust model and no new dev-dependency: sequences come from a small seeded xorshift in the test file.
- **Not ported:** the two deprecated `tryAcquire(maxBurst, rate, period[, tokens])` (owner decision 2). Also `expireAt`, `expireIfSet` and the other `RExpirable` extras, as on every object. Batch view (spec non-goal). Reactive and Rx interfaces.

## The Lua port (`TRY_ACQUIRE_LUA`), for review

```lua
local maxBurst = redis.call('hget', KEYS[1], 'maxBurst');
local rate = redis.call('hget', KEYS[1], 'rate');
local period = redis.call('hget', KEYS[1], 'period');
assert(maxBurst ~= false and rate ~= false and period ~= false, 'GCRA rate is not set');
-- Port of gcraCommand, redis/src/gcra.c (unstable, 2026-11-02). Lua numbers are doubles: 2^53 replaces LLONG_MAX.
local LIMIT = 9007199254740992
local overflowTokens = 'GCRA limiting uses microsecond accuracy. Combination of period, tokens_per_period and TOKENS would cause an overflow'
-- getLongLongFromObject: an integer as string2ll reads it (no sign but '-', no leading zero), within a long long.
local function long(s)
    if s ~= '0' and not string.find(s, '^%-?[1-9]%d*$') then return nil end
    local digits = (string.gsub(s, '^%-', ''))
    local most = '9223372036854775807'
    if string.sub(s, 1, 1) == '-' then most = '9223372036854775808' end
    if #digits > 19 or (#digits == 19 and digits > most) then return nil end
    return tonumber(s)
end
local maxBurstN = long(maxBurst)
if maxBurstN == nil or maxBurstN < 0 then
    return redis.error_reply('value is out of range, must be positive')
end
local burst = maxBurstN + 1
local perPeriod = long(rate)
if perPeriod == nil then return redis.error_reply('value is not an integer or out of range') end
if perPeriod < 1 then
    return redis.error_reply('value is out of range, value must between 1 and 9223372036854775807')
end
local periodS = tonumber(period)
if periodS == nil then return redis.error_reply('value is not a valid float') end
local tokens = tonumber(ARGV[1])
if periodS <= 0 or periodS >= 1e12 then
    return redis.error_reply('period must be > 0 and < 1e12')
end
local time = redis.call('TIME')
-- commandTimeSnapshot() * 1000: whole milliseconds, in microseconds.
local now = tonumber(time[1]) * 1000000 + math.floor(tonumber(time[2]) / 1000) * 1000
local stored = redis.call('GET', KEYS[2])
local tat = now
if stored ~= false then tat = tonumber(stored) end
local emission = math.floor(periodS * 1000000 / perPeriod + 0.5)
if emission == 0 then emission = 1 end
if emission > LIMIT / tokens then return redis.error_reply(overflowTokens) end
if emission > LIMIT / burst then
    return redis.error_reply('GCRA limiting uses microsecond accuracy. Combination of period, tokens_per_period and max_burst would cause an overflow')
end
local variance = emission * burst
local increment = emission * tokens
local base = math.max(now, tat)
if LIMIT - base < increment then return redis.error_reply(overflowTokens) end
local newTat = base + increment
local diff = now - (newTat - variance)
local limited, retry, ttl = 0, -1, 0
if diff < 0 then
    limited = 1
    if increment <= variance then retry = math.ceil(-diff / 1000000) end
    ttl = tat - now
else
    ttl = newTat - now
    redis.call('SET', KEYS[2], string.format('%.0f', newTat), 'PXAT', string.format('%.0f', math.floor(newTat / 1000)))
end
local nextUs = variance - ttl
local remaining = 0
if nextUs >= 0 then remaining = math.floor(nextUs / emission) end -- C truncates toward zero; (-emission, 0) gives 0
return {limited, burst, remaining, retry, math.ceil(ttl / 1000000)}
```

The four `assert` lines are Redisson's, byte for byte, so the "not set" error is the same on both paths.

## Global Constraints

- `#![deny(clippy::unwrap_used, clippy::expect_used, clippy::panic, clippy::todo, clippy::unimplemented)]`: no unwrap/expect in library code. Tests may unwrap.
- Lua: `TRY_SET_RATE`, `SET_RATE` and `TRY_ACQUIRE` are copied verbatim from the line ranges above, with KEYS and ARGV in Redisson's order. `TRY_ACQUIRE_LUA` is exactly the block above. No other new Lua.
- Data: state at the raw name (`Key::new(core, name)`), config at `suffix_name(name, "config")`, fields `maxBurst`, `rate`, `period` (decimal seconds). With `GCRA` on the server, a Redisson client and a redissun client share both keys.
- Minimum server: Redis 6.2 (`SET … PXAT`) or Valkey. The native path needs a Redis build with `GCRA` (only `redis:8.8-m02`/`-m03` today).
- Every public method and field carries `#[doc(alias = "<Redisson name>")]`. `client.gcra` carries `getGcra`.
- `Gcra` is at the crate root with `GcraConfig` and `GcraResult`. `pub mod gcra { pub use crate::coordination::gcra::TryAcquire; }` in `lib.rs`.
- The rustdoc of `Gcra` starts with "**Experimental.**", as do its docs page and README row.
- One cargo build or test run at a time, `--test-threads 4`. No git worktrees.
- Docs go in the task that changes the behaviour: `website/content/docs/objects/gcra.mdx` (new, in `objects/meta.json` after `"rate-limiter"`), `guides/redisson-migration.mdx` (naming row `RGcra` → `Gcra`, `## Gcra` table), `guides/limitations.mdx`, `README.md`.

## Review Focus

1. **The Lua path gives the native replies.** Same algorithm, same rounding (`floor(x + 0.5)`, `ceil`, truncation), the same `max_burst + 1`, `-1` for "never", the same errors. Pinned in Task 3: `lua_matches_native_on_generated_sequences` (the property test), `lua_matches_native_on_errors`.
2. **The probe never writes and caches once.** On 8.8-m03, `EXISTS name` is `0` after the probe. On 7.4 the answer is no. An unclear error (connection, `LOADING`, `TRYAGAIN`, ...) is returned and not cached. Pinned in Task 2 (`the_probe_writes_nothing`) and in unit tests of `probe_answer`.
3. **Mixed state is an error, never a wrong answer.** A Lua-written key on an 8.8-m03 server gives `WRONGTYPE` from `try_acquire`. `set_rate` clears it. Pinned in Task 3 (`a_lua_state_on_a_gcra_server_is_wrongtype_until_reset`).
4. **`retry_after` and `limited`.** `None` while allowed. `Some(≥ 1 s)` while limited and the request fits. `None` while limited with `tokens > max_tokens`. Pinned in Tasks 2 and 3 on both paths (`retry_after_is_none_for_a_request_that_never_fits`).
5. **Interop with Redisson's data.** The config hash fields and the period string match Redisson's (`"0.25"`, `"1"`), `config()` reads hashes that Redisson wrote, and `set_rate` resets the state. Pinned in Task 1 (`config_is_stored_like_redisson`, `config_reads_redissons_period_strings`).
6. **Cluster.** Two keys, one slot, routed by `{name}:config`, for `x` and for `{t}:x`, on both paths. Pinned in Task 4.

## Changelog
### Added
- `Gcra` (experimental; `client.gcra(name)`): `init_rate(max_burst, tokens_per_period, period)`, `set_rate(..)`, `config() -> Option<GcraConfig>`, and `try_acquire()` with `.tokens(n)` → `GcraResult { limited, max_tokens, available_tokens, retry_after: Option<Duration>, full_burst_after }`. `Object` methods cover the state and the config key.

### Behaviour that differs from Redisson on purpose
- On a server without `GCRA`, redissun runs the algorithm in Lua; Redisson fails with "unknown command".

- `TRY_ACQUIRE_LUA`, new: Redisson's config prefix plus a port of `gcraCommand`. - `TRY_SET_RATE`, `SET_RATE` and `TRY_ACQUIRE` are Redisson's, verbatim.
