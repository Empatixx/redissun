# redissun v0.3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Add `Vec`, `VecDeque` and `HashSet` backed by Redis lists and sets, and bump to 0.3.0.

**Architecture:** Each type holds a `Key` and a codec like `HashMap`. `Vec` and `VecDeque` share one paged-`LRANGE` stream helper. Index insert and remove are Lua scripts that use a unique marker value.

**Tech Stack:** fred 10 (`i-lists`, `i-sets`), tokio, serde, testcontainers.

**Spec:** `docs/superpowers/specs/2026-10-08-redissun-v0.3-design.md`

## Global Constraints

- No code comments. Rustdoc `///` on every public item (`#![deny(missing_docs)]`).
- Values are passed borrowed (`&Q`, `V: Borrow<Q>`) and returned owned.
- The crate types `Vec`, `VecDeque`, `HashSet` shadow std names, so inside the crate their modules refer to std `Vec` as `std::vec::Vec` and `client.rs` uses full paths.
- Commit author is the repo-local `Empatixx` identity. Commits end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.
- Tests need `DOCKER_HOST=unix:///Users/jirka/.colima/cdx/docker.sock`.

## Review Focus

- `Vec::insert` and `Vec::remove` with duplicate values and at both ends.
- `Vec::set` and `Vec::insert` past the end give `Error::OutOfRange`, not a Redis error string.
- Iteration over more than one page (250 items) for `Vec`, `VecDeque`, `HashSet`.
- Concurrent push/pop never loses or duplicates an element.
- Set operations when one of the sets does not exist.
