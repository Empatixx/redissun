# redgrid v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and document redgrid v0.1: a Rust library of Redisson-style distributed objects (`Client`, `Codec`, `Bucket`, `Map`, reentrant `Lock` with watchdog) on tokio, serde, `fred` and Lua, with a Fumadocs documentation site.

**Architecture:** One crate. A shared `Core` (fred connection pool, a dedicated pub/sub connection, Lua script runner, owner identity) sits behind `Client`. `Bucket`, `Map` and `Lock` are thin typed handles over a `Key` (core plus name); the `Object` trait is a blanket impl over a sealed `HasKey` trait. Locks are hashes manipulated by Lua scripts; waiters sleep on a `tokio::sync::Notify` fed by pub/sub; a watchdog task renews leases.

**Tech Stack:** Rust 2021, tokio 1, fred 10.1, serde and serde_json, thiserror 2, tokio-util, futures, testcontainers 0.27 with testcontainers-modules 0.15 (Redis 7.4), Fumadocs (Next.js 16, MDX, Tailwind 4) for the site.

**Spec:** `docs/superpowers/specs/2026-10-08-redgrid-v0.1-design.md`

## Global Constraints

- Code contains no comments (user preference). The single exception is Task 8 (rustdoc), which is opt-in and needs the user's explicit yes before it starts.
- Public names: no `R` prefix; `std`/`tokio` names where an equivalent exists, Redis command names in snake_case otherwise (spec "Naming rules").
- No `fred` type appears in the public API. `Error` is `#[non_exhaustive]`. Crate version stays `0.x`.
- Redis or Valkey 6.2 or newer (`SET ... GET` and `GETDEL`); tests pin the `redis:7.4` image.
- Edition 2021. `Cargo.lock` is not committed. No `rust-version` is declared until it has been measured.
- Dependencies are exactly those in the Task 1 `Cargo.toml`; do not add others.
- Tests run against a real Redis. Set `REDGRID_TEST_REDIS_URL` to reuse a running server; otherwise testcontainers starts `redis:7.4`. On this machine Docker is Colima, so prefix cargo commands with `DOCKER_HOST=unix:///Users/jirka/.colima/cdx/docker.sock`. Do not stop or remove containers you did not start; other stacks run on this Docker host.
- The documentation site assumes the GitHub repository is named `redgrid` (`basePath: '/redgrid'`). README badges that need the repository owner are left out until the repository exists.
- `cargo publish`, creating the GitHub repository and reserving the crate name are out of scope; each needs the user's explicit go-ahead.

## Review Focus

The inputs and failure modes the spec implies that most need a pinned test, most likely first. Each is covered by the named test.

1. Lock identity across tasks: two tokio tasks sharing one `Client` must be different owners. `tasks_of_the_same_client_are_distinct_owners` in `tests/lock.rs`.
2. Waiters must wake through pub/sub, not by waiting out the 30 s lease. `waiter_is_woken_by_unlock_long_before_the_lease_expires` in `tests/lock.rs`.
3. Unlocking after the lease expired is `Error::LockNotHeld`, not a panic or silent success. `unlocking_an_expired_lock_reports_lock_not_held` in `tests/lock.rs`.
4. A map larger than one `HSCAN` page streams completely. `iteration_spans_more_than_one_scan_page` in `tests/map.rs`.
5. Empty, unicode and numeric keys, and `null` values, round-trip without being confused with missing keys. `empty_unicode_and_numeric_keys_round_trip` and `null_values_are_distinct_from_missing_keys` in `tests/map.rs`.
6. Data of the wrong type is `Error::Codec`, not a panic. `reading_with_the_wrong_type_is_a_codec_error_not_a_panic` in `tests/bucket.rs`.
7. Bad configuration and an unreachable server fail fast with an error. Five tests in `tests/client.rs`.

## Known limitations (documented in the site, not fixed in v0.1)

- Pub/sub subscriptions created for lock waits are never unsubscribed.
- After a lost connection, missed unlock notifications are recovered only when the lease would have expired.
- A guard dropped outside a tokio runtime cannot release the lock; the lease frees it.

```rust
use crate::error::Result;
use fred::clients::Client as RedisClient;
use fred::interfaces::{ClientLike, EventInterface, PubsubInterface};
use fred::types::Message;
use std::collections::HashMap;
use std::sync::{Arc, Weak};
use tokio::sync::broadcast::error::RecvError;
use tokio::sync::{broadcast, Mutex, Notify};

pub(crate) struct PubSub {
    client: RedisClient,
    channels: Mutex<HashMap<String, Arc<Notify>>>,
}

impl PubSub {
    pub(crate) async fn start(base: &RedisClient) -> Result<Arc<Self>> {
        let client = base.clone_new();
        client.init().await?;
        let receiver = client.message_rx();
        let pubsub = Arc::new(Self {
            client,
            channels: Mutex::new(HashMap::new()),
        });
        tokio::spawn(dispatch(Arc::downgrade(&pubsub), receiver));
        Ok(pubsub)
    }

    pub(crate) async fn subscribe(&self, channel: &str) -> Result<Arc<Notify>> {
        let mut channels = self.channels.lock().await;
        if let Some(notify) = channels.get(channel) {
            return Ok(notify.clone());
        }
        self.client.subscribe(channel).await?;
        let notify = Arc::new(Notify::new());
        channels.insert(channel.to_string(), notify.clone());
        Ok(notify)
    }
}

async fn dispatch(pubsub: Weak<PubSub>, mut receiver: broadcast::Receiver<Message>) {
    loop {
        let message = receiver.recv().await;
        let Some(pubsub) = pubsub.upgrade() else {
            break;
        };
        let channels = pubsub.channels.lock().await;
        match message {
            Ok(message) => {
                if let Some(notify) = channels.get(&message.channel.to_string()) {
                    notify.notify_waiters();
                }
            }
            Err(RecvError::Lagged(_)) => channels.values().for_each(|n| n.notify_waiters()),
            Err(RecvError::Closed) => break,
        }
    }
}
```

- [ ] **Step 6: Create `src/core.rs`**

```rust
use crate::error::{Error, Result};
use crate::pubsub::PubSub;
use bytes::Bytes;
use fred::clients::{Client as RedisClient, Pool};
use fred::interfaces::ClientLike;
use fred::prelude::{Builder, Config, FromValue};
use fred::types::scripts::Script;
use std::sync::Arc;
use std::time::Duration;
use uuid::Uuid;

pub(crate) struct Core {
    pool: Pool,
    id: String,
    pub(crate) lock_lease: Duration,
    pub(crate) pubsub: Arc<PubSub>,
}

impl Core {
    pub(crate) async fn connect(
        url: &str,
        pool_size: usize,
        lock_lease: Duration,
    ) -> Result<Arc<Self>> {
        let config = Config::from_url(url).map_err(|e| Error::Config(e.to_string()))?;
        let pool = Builder::from_config(config)
            .build_pool(pool_size)
            .map_err(|e| Error::Config(e.to_string()))?;
        pool.init().await?;
        let pubsub = PubSub::start(pool.next()).await?;
        Ok(Arc::new(Self {
            pool,
            id: Uuid::new_v4().to_string(),
            lock_lease,
            pubsub,
        }))
    }

    pub(crate) fn redis(&self) -> &RedisClient {
        self.pool.next()
    }

    pub(crate) fn owner(&self) -> String {
```

```rust
use crate::codec::Codec;
use crate::error::Result;
use crate::object::{HasKey, Key};
use bytes::Bytes;
use fred::interfaces::KeysInterface;
use fred::types::scripts::Script;
use fred::types::{Expiration, SetOptions};
use serde::de::DeserializeOwned;
use serde::Serialize;
use std::marker::PhantomData;
use std::sync::LazyLock;
use std::time::Duration;

static COMPARE_AND_SET: LazyLock<Script> = LazyLock::new(|| {
    Script::from_lua(
        "if redis.call('GET', KEYS[1]) == ARGV[1] then
            redis.call('SET', KEYS[1], ARGV[2])
            return 1
        end
        return 0",
    )
});

pub struct Bucket<V, C: Codec> {
    key: Key,
    codec: C,
    _marker: PhantomData<fn() -> V>,
}

impl<V, C: Codec> Clone for Bucket<V, C> {
    fn clone(&self) -> Self {
        Self {
            key: self.key.clone(),
            codec: self.codec.clone(),
            _marker: PhantomData,
        }
    }
}

impl<V, C: Codec> HasKey for Bucket<V, C> {
    fn key(&self) -> &Key {
        &self.key
    }
}

impl<V, C: Codec> Bucket<V, C> {
    pub(crate) fn new(key: Key, codec: C) -> Self {
        Self {
            key,
            codec,
            _marker: PhantomData,
        }
    }
}

impl<V, C> Bucket<V, C>
where
    V: Serialize + DeserializeOwned + Send + Sync,
    C: Codec,
{
    pub async fn set(&self, value: &V) -> Result<()> {
        let bytes = self.codec.encode(value)?;
        self.key
            .core
            .redis()
            .set::<(), _, _>(self.key.redis_key(), bytes, None, None, false)
            .await?;
        Ok(())
    }

    pub async fn get(&self) -> Result<Option<V>> {
        let raw: Option<Bytes> = self.key.core.redis().get(self.key.redis_key()).await?;
        raw.map(|bytes| self.codec.decode(&bytes)).transpose()
    }

    pub async fn set_ex(&self, value: &V, ttl: Duration) -> Result<()> {
        let bytes = self.codec.encode(value)?;
        self.key
            .core
            .redis()
            .set::<(), _, _>(
                self.key.redis_key(),
                bytes,
                Some(Expiration::PX(ttl.as_millis() as i64)),
                None,
                false,
            )
            .await?;
        Ok(())
    }

    pub async fn set_nx(&self, value: &V) -> Result<bool> {
        let bytes = self.codec.encode(value)?;
        let stored: Option<String> = self
            .key
            .core
            .redis()
            .set(
                self.key.redis_key(),
                bytes,
                None,
                Some(SetOptions::NX),
                false,
            )
            .await?;
        Ok(stored.is_some())
    }

    pub async fn get_set(&self, value: &V) -> Result<Option<V>> {
        let bytes = self.codec.encode(value)?;
        let previous: Option<Bytes> = self
            .key
            .core
            .redis()
            .set(self.key.redis_key(), bytes, None, None, true)
            .await?;
        previous.map(|bytes| self.codec.decode(&bytes)).transpose()
    }

    pub async fn get_del(&self) -> Result<Option<V>> {
        let previous: Option<Bytes> = self.key.core.redis().getdel(self.key.redis_key()).await?;
        previous.map(|bytes| self.codec.decode(&bytes)).transpose()
    }

    pub async fn compare_and_set(&self, expected: &V, new: &V) -> Result<bool> {
        let swapped: i64 = self
            .key
            .core
            .eval(
                &COMPARE_AND_SET,
                vec![self.key.redis_key()],
                vec![self.codec.encode(expected)?, self.codec.encode(new)?],
            )
            .await?;
        Ok(swapped == 1)
    }
}
```

```rust
use crate::lock::release;
use crate::object::Key;

struct Held {
    key: Key,
    owner: String,
    lease: Duration,
    cancel: CancellationToken,
    runtime: Option<Handle>,
}

#[must_use = "dropping the guard releases the lock in the background; call unlock().await to release it deterministically"]
pub struct LockGuard {
    held: Option<Held>,
}

impl LockGuard {
    pub(crate) fn new(key: Key, owner: String, lease: Duration, cancel: CancellationToken) -> Self {
        Self {
            held: Some(Held {
                key,
                owner,
                lease,
                cancel,
                runtime: Handle::try_current().ok(),
            }),
        }
    }

    pub async fn unlock(mut self) -> Result<()> {
        let Some(held) = self.held.take() else {
            return Ok(());
        };
        held.cancel.cancel();
        release(&held.key, &held.owner, held.lease).await
    }
}

impl Drop for LockGuard {
    fn drop(&mut self) {
        let Some(held) = self.held.take() else {
            return;
        };
        held.cancel.cancel();
        if let Some(runtime) = held.runtime {
            runtime.spawn(async move {
                let _ = release(&held.key, &held.owner, held.lease).await;
            });
        }
    }
}
```

```rust
    fn key(&self) -> &Key {
        &self.key
    }
}

impl Lock {
    pub(crate) fn new(key: Key) -> Self {
        Self { key }
    }

    pub async fn lock(&self) -> Result<LockGuard> {
        self.lock_with(LockOptions::new())
            .await?
            .ok_or(Error::Timeout)
    }

    pub async fn try_lock(&self) -> Result<Option<LockGuard>> {
        self.lock_with(LockOptions::new().wait(Duration::ZERO))
            .await
    }

    pub async fn lock_for(&self, wait: Duration) -> Result<Option<LockGuard>> {
        self.lock_with(LockOptions::new().wait(wait)).await
    }

    pub async fn lock_with(&self, options: LockOptions) -> Result<Option<LockGuard>> {
        let core = &self.key.core;
        let owner = core.owner();
        let watchdog = options.lease.is_none();
        let lease = options.lease.unwrap_or(core.lock_lease);
        let deadline = options.wait.map(|wait| Instant::now() + wait);
        let notify = match options.wait {
            Some(wait) if wait.is_zero() => Arc::new(Notify::new()),
            _ => core.pubsub.subscribe(&channel(self.key.name())).await?,
        };

        loop {
            let notified = notify.notified();
            tokio::pin!(notified);
            notified.as_mut().enable();

            let pttl: Option<i64> = core
                .eval(
                    &ACQUIRE,
                    vec![self.key.redis_key()],
                    vec![millis(lease), Bytes::from(owner.clone())],
                )
                .await?;

            let Some(pttl) = pttl else {
                let cancel = CancellationToken::new();
                if watchdog {
                    watchdog::spawn(self.key.clone(), owner.clone(), lease, cancel.clone());
                }
                return Ok(Some(LockGuard::new(self.key.clone(), owner, lease, cancel)));
            };

            let remaining = match deadline {
                Some(deadline) => {
                    let remaining = deadline.saturating_duration_since(Instant::now());
                    if remaining.is_zero() {
                        return Ok(None);
                    }
                    Some(remaining)
                }
                None => None,
            };
            let until_expiry = if pttl > 0 {
                Duration::from_millis(pttl as u64)
            } else {
                NO_EXPIRY_POLL
            };
            let pause = remaining.map_or(until_expiry, |r| r.min(until_expiry));
            let _ = tokio::time::timeout(pause, notified).await;
        }
    }

    pub async fn is_locked(&self) -> Result<bool> {
        let found: i64 = self.key.core.redis().exists(self.key.redis_key()).await?;
        Ok(found > 0)
    }

    pub async fn is_held_by_current(&self) -> Result<bool> {
        let held: bool = self
            .key
            .core
            .redis()
            .hexists(self.key.redis_key(), self.key.core.owner())
            .await?;
        Ok(held)
    }

    pub async fn hold_count(&self) -> Result<u64> {
        let count: Option<u64> = self
            .key
            .core
            .redis()
            .hget(self.key.redis_key(), self.key.core.owner())
            .await?;
        Ok(count.unwrap_or(0))
    }

    pub async fn force_unlock(&self) -> Result<bool> {
        let removed: i64 = self
            .key
            .core
            .eval(
                &FORCE_UNLOCK,
                vec![self.key.redis_key()],
                vec![Bytes::from(channel(self.key.name()))],
            )
            .await?;
        Ok(removed == 1)
    }
}
```

````markdown
# redgrid

Distributed objects on Redis for Rust, closely inspired by [Redisson](https://github.com/redisson/redisson).

[![crates.io](https://img.shields.io/crates/v/redgrid.svg)](https://crates.io/crates/redgrid)
[![docs.rs](https://img.shields.io/docsrs/redgrid)](https://docs.rs/redgrid)
[![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)

Named objects that live in Redis and behave like their in-process counterparts, shared by every process that connects to the same server. Async on tokio, values through serde, atomic operations through Lua.

## Quick start

```rust
use redgrid::Client;

#[tokio::main]
async fn main() -> redgrid::Result<()> {
    let client = Client::builder().url("redis://127.0.0.1:6379").build().await?;

    let users = client.map::<String, String>("users");
    users.insert("jirka".into(), "Jirka".into()).await?;
    println!("{:?}", users.get("jirka").await?);

    let lock = client.lock("order:42");
    let guard = lock.lock().await?;
    guard.unlock().await?;

    Ok(())
}
```

## Objects

| redgrid | Redisson | Redis type | Since |
|---|---|---|---|
| `Bucket` | `RBucket` | string | 0.1 |
| `Map` | `RMap` | hash | 0.1 |
| `Lock` | `RLock` | hash and pub/sub | 0.1 |

More objects (`List`, `Set`, `AtomicLong`, `Topic`, `Semaphore`, `RateLimiter`, `MapCache`) ship one per release.

## Design

- Method names follow `std` and `tokio` where an equivalent exists (`insert`, `get`, `len`, `lock`, `try_lock`) and Redis command names otherwise (`set_nx`, `incr_by`, `expire`, `ttl`).
- `Lock` is reentrant, kept alive by a watchdog, and wakes waiters through pub/sub instead of polling.
- The Redis client is an implementation detail; no `fred` type appears in the public API.

## Requirements

Redis or Valkey 6.2 or newer.

## Documentation

- Guides and migration table from Redisson: the `website/` directory, published with GitHub Pages.
- API reference: [docs.rs/redgrid](https://docs.rs/redgrid).
- Examples: [`examples/`](examples).
````

```markdown
---
title: Introduction
description: Distributed objects on Redis for Rust, closely inspired by Redisson.
---

redgrid brings the Redisson programming model to Rust: named objects that live in Redis and behave like their in-process counterparts, shared by every process that connects to the same server.

## What you get

| Object | Redis type | Redisson counterpart |
|---|---|---|
| `Bucket` | string | `RBucket` |
| `Map` | hash | `RMap` |
| `Lock` | hash and pub/sub | `RLock` |

- Async on tokio, no blocking calls.
- Values are encoded through a `Codec`; JSON through serde is the default.
- Everything that must be atomic runs as a Lua script.
- `Lock` is reentrant, renewed by a watchdog and woken through pub/sub instead of polling.
- Method names follow `std` and `tokio` where an equivalent exists, and Redis command names otherwise.

## Requirements

Redis or Valkey 6.2 or newer. Connections go through the `fred` client, so standalone, cluster and sentinel deployments are supported by the underlying library.

## Where to go next

- [Installation](/docs/getting-started/installation)
- [Quick start](/docs/getting-started/quick-start)
- [Migrating from Redisson](/docs/guides/redisson-migration)
```

````markdown
---
title: Quick Start
description: Connect, store a value, fill a map and take a lock.
---

```rust
use redgrid::{Client, Object};
use serde::{Deserialize, Serialize};

#[derive(Serialize, Deserialize)]
struct User {
    name: String,
}

#[tokio::main]
async fn main() -> redgrid::Result<()> {
    let client = Client::builder().url("redis://127.0.0.1:6379").build().await?;

    let motd = client.bucket::<String>("motd");
    motd.set(&"hello".to_string()).await?;

    let users = client.map::<String, User>("users");
    users.insert("jirka".into(), User { name: "Jirka".into() }).await?;
    let found = users.get("jirka").await?;

    let lock = client.lock("order:42");
    let guard = lock.lock().await?;
    guard.unlock().await?;

    Ok(())
}
```

## Cloning the client

`Client` is cheap to clone and every clone shares the same connection pool. Create it once and pass clones to the tasks that need it.

## Errors

Every fallible call returns `redgrid::Result`. `Error` is non-exhaustive, so match with a wildcard arm.

```rust
match lock.try_lock().await {
    Ok(Some(guard)) => guard.unlock().await?,
    Ok(None) => println!("busy"),
    Err(error) => return Err(error),
}
```
````

````markdown
`Bucket` stores one value as a Redis string.

let bucket = client.bucket::<String>("greeting");

## Methods

| Method | Redis | Returns |
|---|---|---|
| `set(&v)` | `SET` | `()` |

| Method | Redis |

| `rename(new_name)` | `RENAME` |
````

- [ ] **Step 21: Create `website/content/docs/objects/map.mdx`**

````markdown
---
title: Map
description: A distributed map with HashMap-style methods.
---

`Map` stores entries in a Redis hash. Keys and values both go through the codec.

```rust
let users = client.map::<String, User>("users");

users.insert("jirka".into(), user).await?;
let found = users.get("jirka").await?;
```

Lookups take a borrowed key, like `HashMap::get`, so `users.get("jirka")` does not allocate a `String`.

## Methods

| Method | Redis | Notes |
|---|---|---|
| `insert(k, v)` | Lua | returns the previous value |
| `get(&k)` | `HGET` | |
| `remove(&k)` | Lua | returns the removed value |
| `contains_key(&k)` | `HEXISTS` | |
| `len()` / `is_empty()` | `HLEN` | |
| `clear()` | `DEL` | |
| `extend(entries)` | `HSET` | one round trip, empty input is a no-op |
| `get_many(&[&k])` | `HMGET` | order matches the input |
| `insert_nx(k, v)` | `HSETNX` | true when inserted |
| `incr_by(&k, delta)` | `HINCRBY` | creates the field at zero |
| `incr_by_float(&k, delta)` | `HINCRBYFLOAT` | |

`incr_by` and `incr_by_float` need values that the codec writes as plain numbers, which is the case for integers and floats with the default JSON codec.

## Iteration

`iter`, `keys` and `values` return a `Stream` built on `HSCAN`. The hash is read in pages of 100 entries and never loaded at once.

```rust
use futures::TryStreamExt;

let entries: Vec<(String, User)> = users.iter().try_collect().await?;
```

## Missing keys and null values

`get` returns `None` for a missing key. When the value type is itself an `Option`, a stored `None` comes back as `Some(None)`, so the two cases stay distinguishable.
````

- [ ] **Step 22: Create `website/content/docs/objects/lock.mdx`**

````markdown
---
title: Lock
description: A reentrant distributed lock with a watchdog.
---

`Lock` is the equivalent of Redisson's `RLock`, shaped like `tokio::sync::Mutex`.

```rust
let lock = client.lock("order:42");

let guard = lock.lock().await?;
guard.unlock().await?;
```

## Acquiring

| Method | Behaviour |
|---|---|
| `lock()` | waits until the lock is free |
| `try_lock()` | returns `None` at once when the lock is taken |
| `lock_for(wait)` | returns `None` when `wait` runs out |
| `lock_with(options)` | full control through `LockOptions` |

```rust
use redgrid::LockOptions;
use std::time::Duration;

let options = LockOptions::new().wait(Duration::from_secs(2)).lease(Duration::from_secs(10));
let guard = lock.lock_with(options).await?;
```

## Releasing

Call `guard.unlock().await` to release deterministically and to see errors. Unlocking a lock whose lease already expired returns `Error::LockNotHeld`.

Dropping the guard also releases the lock, in a background task on the runtime that created it. Prefer the explicit call.

## Reentrancy

The same owner can take the lock repeatedly; each acquisition needs its own unlock. `hold_count()` shows how many are outstanding.

An owner is a client plus a tokio task, which replaces the thread id used in Java. Two tasks that share a `Client` are different owners and exclude each other.

## Lease and watchdog

Without an explicit lease the lock lives for the client's `lock_lease` (30 seconds by default, set through `Client::builder().lock_lease(..)`) and a watchdog renews it every third of that period while the guard is alive. A process that crashes stops renewing, and the lock frees itself when the lease runs out.

With an explicit `lease` there is no watchdog and the lock expires when the lease does.

## Waiting without polling

Waiters subscribe to a pub/sub channel and wake as soon as the holder unlocks. If a notification is missed, the waiter wakes when the current lease would expire.

## Inspection

| Method | Meaning |
|---|---|
| `is_locked()` | any owner holds it |
| `is_held_by_current()` | the calling task holds it |
| `hold_count()` | reentrant count for the calling task |
| `force_unlock()` | releases it regardless of the owner |
````

```markdown
---
title: Migrating from Redisson
description: How Redisson names and behaviour map to redgrid.
---

## Naming

| Redisson | redgrid |
|---|---|
| `RBucket` | `Bucket` |
| `RMap` | `Map` |
| `RLock` | `Lock` |
| `redisson.getMap("x")` | `client.map("x")` |
| `redisson.getLock("x")` | `client.lock("x")` |

## Bucket

| Redisson | redgrid |
|---|---|
| `set(v)` | `set(&v)` |
| `set(v, ttl)` | `set_ex(&v, ttl)` |
| `get()` | `get()` |
| `trySet(v)` | `set_nx(&v)` |
| `getAndSet(v)` | `get_set(&v)` |
| `getAndDelete()` | `get_del()` |
| `compareAndSet(e, n)` | `compare_and_set(&e, &n)` |

## Map

| Redisson | redgrid |
|---|---|
| `put(k, v)` | `insert(k, v)` |
| `get(k)` | `get(&k)` |
| `remove(k)` | `remove(&k)` |
| `containsKey(k)` | `contains_key(&k)` |
| `size()` | `len()` |
| `putAll(m)` | `extend(entries)` |
| `getAll(keys)` | `get_many(&keys)` |
| `putIfAbsent(k, v)` | `insert_nx(k, v)` |
| `addAndGet(k, d)` | `incr_by(&k, d)` or `incr_by_float(&k, d)` |
| `keySet()`, `values()`, `entrySet()` | `keys()`, `values()`, `iter()` as streams |

`putIfAbsent` returns the existing value in Java. `insert_nx` returns whether the entry was inserted.

## Lock

| Redisson | redgrid |
|---|---|
| `lock()` | `lock().await` |
| `tryLock()` | `try_lock().await` |
| `tryLock(wait, unit)` | `lock_for(wait).await` |
| `tryLock(wait, lease, unit)` | `lock_with(LockOptions::new().wait(w).lease(l)).await` |
| `unlock()` | `guard.unlock().await` |
| `isLocked()` | `is_locked().await` |
| `isHeldByCurrentThread()` | `is_held_by_current().await` |
| `getHoldCount()` | `hold_count().await` |
| `forceUnlock()` | `force_unlock().await` |
| `lockWatchdogTimeout` | `Client::builder().lock_lease(..)` |

## Behavioural differences

- The lock owner is a client and a tokio task, not a thread.
- Unlocking goes through a guard value. Unlocking something you do not hold is `Error::LockNotHeld` instead of an `IllegalMonitorStateException`.
- Values use a serde codec rather than Redisson's Java codecs, so data written by Redisson is not readable by redgrid and the other way round.
- Only `Bucket`, `Map` and `Lock` exist in 0.1.
```

- [ ] **Step 25: Create `website/content/docs/guides/limitations.mdx`**

```markdown
---
title: Limitations
description: Known constraints of the current release.
---

- **Redis 6.2 or newer** is required for `Bucket::get_set` and `Bucket::get_del`.
- **Pub/sub subscriptions are kept.** A lock name that has been waited on stays subscribed for the life of the client, so a process that waits on an unbounded set of distinct lock names grows its subscription table.
- **Missed notifications** after a lost connection are recovered by the lease expiry, not immediately.
- **Dropping a guard without a runtime** cannot release the lock; it frees itself when the lease expires.
- **Cluster:** `Bucket::rename` and `Object::rename` can fail across hash slots, as `RENAME` does in Redis Cluster itself.
- **Numeric operations** such as `Map::incr_by` need values the codec writes as plain numbers.
- Pre-1.0 releases may change the API between minor versions.
```
