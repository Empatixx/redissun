# redissun v0.7 design

## Goal

Two additions, chosen by the user: `FairLock` and `SortedSet`.

## FairLock

`client.fair_lock(name)` returns a `FairLock`. It is a `Lock` that serves waiters in arrival order. The scheme is taken from Redisson's `RedissonFairLock`.

- Keys share the hash tag `{name}`: the hash `{name}` (the lock, owner to hold count), the list `redissun__lock_queue:{name}` (waiters in order) and the sorted set `redissun__lock_timeout:{name}` (owner to the time when it loses its place).
- A caller gets the lock only when the lock is free and the queue is empty or the caller is first. Otherwise it is added to the queue with the time `wait of the head + 5 seconds + now`, and the script returns the time to wait.
- Every script first drops queue heads whose time has passed, so a crashed waiter cannot block the others.
- Time comes from the Redis server (`TIME` inside the script), not from the clients.
- Every waiter listens on its own channel `redissun__unlock__{name}:{owner}`. A release, a force unlock and a leaving waiter publish only to the head of the queue.
- A waiter that times out or is cancelled runs a cancel script: it leaves the queue, shifts the times of the others when it was first, and wakes the new head when the lock is free. Dropping the pending call does this in the background.
- `lock()` returns the same `LockRequest` as `Lock` (`.timeout`, `.lease`). `try_lock()` never jumps the queue. The guard is the `LockGuard`, and the watchdog and renew script are shared with `Lock`.
- Methods: `lock`, `try_lock`, `is_locked`, `is_held_by_current`, `hold_count`, `queue_len`, `force_unlock`. It implements `Object`, and `companions` returns the queue and the timeout keys.

## SortedSet

`client.sorted_set::<V>(name)` returns a `SortedSet<V, C>` over a Redis sorted set. It is the std-less counterpart of Redisson's `RScoredSortedSet`, so it keeps the Redis-like name.

- Scores are `f64`. Values are passed borrowed and returned owned, together with their score as `(V, f64)`.
- Methods: `insert(&v, score) -> bool`, `add_score`, `score`, `remove`, `contains`, `rank`, `rev_rank`, `len`, `is_empty`, `clear`, `first`, `last`, `pop_first`, `pop_last`, `range(a..b)`, `rev_range(a..b)` (exclusive end), `range_by_score(min, max)`, `count_by_score`, `remove_by_score` (both ends included), `iter()` (pages of 100).
- It implements `Object`.

## Testing

Integration tests against real Redis: FIFO order for several waiters, `try_lock` does not jump the queue, timeout and cancellation leave the queue and do not block the next waiter, lease expiry hands the lock over, force unlock wakes the first waiter, cross-client use, `Object` covers the companion keys. SortedSet: every method, equal scores, paging over 250 values, structured values, concurrent pops, `Object` methods.

## Out of scope

Blocking pops on `SortedSet`, set operations between sorted sets, lexicographic ranges, `MultiLock`, a fair `RwLock`.
