# redissun v0.1 design

## Purpose

`redissun` is an open-source Rust library of distributed objects on top of Redis, closely inspired by Java's Redisson. It fills a gap in the Rust ecosystem, where only isolated Redlock crates exist (`rslock`, `redlock`, `rdlock`) and nothing offers distributed collections, locks and synchronizers behind one API.

Goals:

- Published on crates.io with a stable, small public API and full documentation.
- Behaviour faithful to Redisson (reentrant lock with watchdog, atomic operations via Lua, pub/sub notifications), names faithful to Rust.
- Async on tokio, serde-based codec.

Non-goals for v0.1: `MapCache`, `List`, `Set`, `Topic`, `Semaphore`, `RateLimiter`, `AtomicLong`, queues, streams, transactions, batch, sentinel and cluster tuning beyond what `fred` provides out of the box.

## Naming rules

- No `R` prefix. Types live in the crate namespace: `redissun::Map`, `redissun::Lock`.
- Factory methods without `get_`: `client.map("users")`, `client.lock("order:42")`.
- Where `std` or `tokio` has an equivalent, use its name and semantics: `insert`, `get`, `remove`, `contains_key`, `len`, `is_empty`, `clear`, `extend`, `lock`, `try_lock`.
- Where `std` has no equivalent, use the Redis command name in snake_case: `set_nx`, `incr_by`, `expire`, `ttl`, `persist`, `del`, `exists`, `rename`.
- Lookups take `&Q where K: Borrow<Q>`, like `HashMap::get`.

## Public API

```rust
pub struct Client;
pub struct ClientBuilder;
pub struct Bucket<V, C = JsonCodec>;
pub struct Map<K, V, C = JsonCodec>;
pub struct Lock;
pub struct LockGuard;
pub trait Codec: Send + Sync + 'static;
pub struct JsonCodec;
#[non_exhaustive] pub enum Error;
pub type Result<T> = std::result::Result<T, Error>;
```

- `Client::builder().url(..).codec(..).build().await` returns a `Client`. `Client` is cheap to clone (`Arc` inside).
- Builder settings: `url` (required), `pool_size` (default 4, at least 1), `lock_lease` (default 30 s, the lease used when a lock has no explicit one), `connect_timeout` (default 10 s), `codec`.
- `fred` types never appear in the public API, so the backend can be replaced without a breaking change.
- `Error` is `#[non_exhaustive]`. Crate version stays `0.x` until the API proves stable.
- `serde_json` is a required dependency in v0.1, so `JsonCodec` is always available. `bincode` and `msgpack` codecs arrive later behind feature flags.

### Object trait

Implemented by `Bucket`, `Map`, `Lock`.

```rust
pub trait Object {
    fn name(&self) -> &str;
    async fn del(&self) -> Result<bool>;
    async fn exists(&self) -> Result<bool>;
    async fn rename(&self, new_name: &str) -> Result<()>;
    async fn expire(&self, ttl: Duration) -> Result<bool>;
    async fn ttl(&self) -> Result<Option<Duration>>;
    async fn persist(&self) -> Result<bool>;
}
```

### Bucket<V>

Redis `string`.

```rust
set(&self, v: &V) -> Result<()>
get(&self) -> Result<Option<V>>
set_ex(&self, v: &V, ttl: Duration) -> Result<()>
set_nx(&self, v: &V) -> Result<bool>
get_set(&self, v: &V) -> Result<Option<V>>
get_del(&self) -> Result<Option<V>>
compare_and_set(&self, expected: &V, new: &V) -> Result<bool>
```

`compare_and_set` is a Lua script.

### Map<K, V>

Redis `hash`; keys and values encoded by the codec.

```rust
insert(&self, k: K, v: V) -> Result<Option<V>>
get<Q>(&self, k: &Q) -> Result<Option<V>>
remove<Q>(&self, k: &Q) -> Result<Option<V>>
contains_key<Q>(&self, k: &Q) -> Result<bool>
len(&self) -> Result<usize>
is_empty(&self) -> Result<bool>
clear(&self) -> Result<()>
extend(&self, iter: impl IntoIterator<Item = (K, V)>) -> Result<()>
get_many<Q>(&self, ks: &[&Q]) -> Result<Vec<Option<V>>>
insert_nx(&self, k: K, v: V) -> Result<bool>
incr_by<Q>(&self, k: &Q, delta: i64) -> Result<i64>
incr_by_float<Q>(&self, k: &Q, delta: f64) -> Result<f64>
keys(&self) -> impl Stream<Item = Result<K>>
values(&self) -> impl Stream<Item = Result<V>>
iter(&self) -> impl Stream<Item = Result<(K, V)>>
```

`keys`, `values`, `iter` are backed by `HSCAN`, so the full map is never loaded at once. `insert` returns the previous value through a Lua `HGET` + `HSET`.

### Lock

Reentrant, equivalent to Redisson `RLock`, modelled on `tokio::sync::Mutex`.

```rust
lock(&self) -> Result<LockGuard>
try_lock(&self) -> Result<Option<LockGuard>>
lock_for(&self, wait: Duration) -> Result<Option<LockGuard>>
lock_with(&self, opts: LockOptions) -> Result<Option<LockGuard>>
is_locked(&self) -> Result<bool>
is_held_by_current(&self) -> Result<bool>
hold_count(&self) -> Result<u64>
force_unlock(&self) -> Result<bool>

LockGuard::unlock(self) -> Result<()>
```

Mechanics:

- Redis `hash` under the lock name; field `<client_uuid>:<task_id>`, value is the reentrancy count. The identity replaces Java's `threadId`, since tokio tasks do not map to threads.
- Acquire and release are Lua scripts (`HINCRBY` + `PEXPIRE`; decrement, `DEL` on zero, `PUBLISH` unlock).
- Waiters subscribe to `redissun__unlock__{name}` and wake via `tokio::sync::Notify`. No spin-polling, one subscription per lock name per client.
- **Watchdog**: with no explicit `lease`, the default lease is 30 s and a background task renews it every 10 s. It stops through a `CancellationToken` owned by the guard.
- `LockGuard::unlock().await` is the explicit release. `Drop` is a safety net that spawns the release on a stored tokio `Handle`.
- Errors: `Error::LockNotHeld`, `Error::Timeout`.

## Backend

`fred` for connection pool, cluster, sentinel, pub/sub with automatic resubscribe and `Script`/`EVALSHA`. It sits behind an internal `Backend` abstraction that is not public in v0.1. Connections reconnect with exponential backoff. When the last `Client` clone is dropped its connections are closed. TTLs and leases are rounded up to whole milliseconds and zero is rejected. Redis or Valkey 6.2 or newer is required (`SET ... GET`, `GETDEL`).

## Testing

- Integration tests against real Redis via testcontainers, one key prefix per test.
- Unit tests for codec round-trips and Lua scripts.
- Lock tests: reentrancy, expiry, watchdog renewal, release notification, contention across clients, `Drop` fallback.
- CI: `fmt`, `clippy -D warnings`, `test` with Redis service container.

## Release plan

v0.1 ships `Client`, `Codec`, `Bucket`, `Map`, `Lock`. Further objects ship incrementally, one per release (`List`, `Set`, `AtomicLong`, `Topic`, `Semaphore`, `RateLimiter`, then `MapCache`, `SortedSet`, queues, `Stream`).
