# redissun v0.3 design

## Goal

Add Redisson's collections to redissun with Rust ownership and the Redisson names without the `R` prefix: `List`, `Deque`, `Set`.

Scope is what the user chose: the three collections. Blocking queues, `Topic`, `MapCache`, sorted sets and the other lock kinds are out of scope.

## How Redisson does it (read from its source) and what we copy

| Piece | Redisson | redissun |
|---|---|---|
| List | Redis list. Index reads are `LINDEX`, writes are `LSET`. `remove(index)` is a Lua script: `LSET` a marker, then `LREM 1` of the marker. `insert(index)` is a Lua script that moves the tail. | same data type and the same two scripts |
| Queue and deque | the same Redis list: `RPUSH` offer, `LPOP` poll, `LINDEX` peek, and the mirror calls for the other end | `Deque` over the same list |
| Set | Redis set: `SADD`, `SREM`, `SISMEMBER`, `SCARD`, `SSCAN`, `SPOP`, `SRANDMEMBER`, `SMOVE`, `SUNION`, `SINTER`, `SDIFF` | same commands |
| Iteration | list pages through `LRANGE`, set uses `SSCAN` | same, as streams |

## Types

- `List<V>` is Redisson's `RList`: a Redis list with index access. Factory: `client.list(name)`.
- `Deque<V>` is Redisson's `RDeque`: the same Redis list seen from its ends. Factory: `client.deque(name)`.
- `Set<V>` is Redisson's `RSet`: a Redis set. Factory: `client.set(name)`.
- All three implement `Object`.
- `List` and `Deque` are two views of one Redis list. Opening both under one name is allowed.
- Names follow the existing rule: the Redisson name without `R`. Methods stay in Rust style (`push`, `pop`, `get`, `insert`).
- Values are passed borrowed (`&Q` where `V: Borrow<Q>`) and returned owned, like `Map`.

## API

`List` (index access):
- `push(&v)`, `pop() -> Option<V>`, `len`, `is_empty`, `clear`.
- `get(i) -> Option<V>`, `set(i, &v)`. Setting an index that does not exist is `Error::OutOfRange`.
- `insert(i, &v)`, `remove(i) -> Option<V>`. Both run as one Lua script and cost O(n).
- `range(start, stop) -> Vec<V>`, `trim(start, stop)`.
- `position(&v) -> Option<usize>` (`LPOS`), `contains(&v)`.
- `remove_value(&v) -> bool` removes the first match. `remove_all(&v) -> usize` removes every match.
- `extend(&[..])` pushes many in one round trip.
- `iter()` is a stream that reads `LRANGE` pages. Concurrent changes can make it skip or repeat an element.

`Deque` (ends):
- `push_back(&v)`, `push_front(&v)`.
- `pop_back()`, `pop_front()` return `Option<V>`.
- `front()`, `back()` read without removing.
- `len`, `is_empty`, `clear`, `iter()`.
- Blocking pops are not in this release.

`Set`:
- `insert(&v) -> bool`, `remove(&v) -> bool`, `contains(&v)`, `contains_many(&[..]) -> Vec<bool>` (`SMISMEMBER`), `len`, `is_empty`, `clear`, `extend`.
- `pop() -> Option<V>`, `random() -> Option<V>`, `move_to(&other, &v) -> bool`.
- `iter()` is a stream over `SSCAN`. An element that was present the whole time is returned at least once. It can be returned twice.
- `union`, `intersection`, `difference` take other sets and return `Vec<V>`. They only read. The `*_into` variants that store the result are not in this release.

## Things to document

- Equality is decided by the encoded bytes, so the codec must be deterministic. `JsonCodec` is fine for structs and not for `HashMap` values.
- Set operations touch several keys. In Redis Cluster the sets must live in one slot, otherwise Redis returns an error.
- Minimum Redis version is 6.2 (`SMISMEMBER`, `LPOS`). CI already uses 7.4.

## Errors

New variant `Error::OutOfRange` for `List::set` on a missing index. Everything else reuses the existing errors.

## Testing

Integration tests against real Redis for every method:
- Order and content after push, insert, remove and trim.
- Both ends of `Deque`, and `List` and `Deque` seeing the same data.
- Missing keys and empty collections.
- Set semantics: duplicates, `move_to`, set operations with a missing set.
- `Object` behaviour: `del`, `exists`, `rename`, `expire`, `ttl`, `persist`.
- Concurrency: many tasks pushing and popping must neither lose nor duplicate an element.
- Iteration over more than one page, for `List` and `Set`.
- Borrowed arguments compile for `&str` against `String` values.

## Out of scope

`BlockingQueue`, `Topic`, `SortedSet`, `MapCache`, `ReadWriteLock`, `FairLock`, `MultiLock`, `*_into` set operations, blocking pops.
