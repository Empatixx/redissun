# redissun v0.6 design

## Goal

Finish `HashMapCache` as a port of Redisson's `RMapCache`: a maximum size with LRU or LFU eviction, and entry listeners.

## Maximum size

Taken from Redisson's `setMaxSize` and `trySetMaxSize`. Two keys are added:

- `redissun__map_cache_options:{name}` (hash): `max-size`, `mode` (`LRU` or `LFU`), `has-listeners`.
- `redissun__map_cache_last_access__set:{name}` (sorted set): for `LRU` the time of the last use, for `LFU` a use counter.

`HashMapCache::set_max_size(max, mode)` writes the options. `0` means unlimited. `try_set_max_size` uses `HSETNX`. Every script reads the options first, so the limit applies to all clients.

A `get` and an `insert` count as use. After an insert, if the hash is larger than `max-size`, the script drops the entries with the lowest score in the access set, but never the entry that was just inserted. Redisson makes room before it inserts. Doing it after is the same result and does not need a special case for an insert over an existing key. Entries without a score, for example those inserted before the limit was set, are not candidates, as in Redisson.

## Entry listeners

Redisson publishes created, updated, removed and expired events on four channels, but only when the options hash has `has-listeners`. redissun publishes on one channel, `redissun__map_cache_events:{name}`, with the same condition. The payload is `<kind><key length>:<value length>:<key><value><previous value>`, where kind is `C`, `U`, `R` or `E`. The lengths make it safe for binary keys and values. Redisson packs the same with `struct.pack`.

`HashMapCache::events()` sets `has-listeners`, subscribes through the shared `PubSub` (the same way as `Topic`) and returns `Events`. `Events::recv()` returns `Event::{Created, Updated, Removed, Expired}` and `Events::into_stream()` a stream. Slow listeners get `Error::Lagged`, as `Topic` subscribers do.

Events by script:

- `insert` and `insert_nx`: `Created`, or `Updated` with the previous value.
- `remove`, and the size eviction: `Removed`.
- Lazy deletion on a read, `evict_expired` and the background task: `Expired`.

`has-listeners` is never cleared, as in Redisson. It costs one extra `PUBLISH` per change after the first listener.

## Object

`del`, `expire` and `persist` cover the options and the access set too. `clear` keeps the options, so a size limit survives it.

## Testing

LRU and LFU eviction, a limit shared by two handles, removing the limit, `try_set_max_size`, each event kind (also for keys and values that contain `:`), size evictions as `Removed`, expiry as `Expired`, several listeners, no publishing before the first listener, and `clear` against `del` for the options.
