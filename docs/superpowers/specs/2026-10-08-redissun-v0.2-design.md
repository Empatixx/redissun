# redissun v0.2 design

## Goal

Add Redisson's synchronizers to redissun, built the way Redisson builds them internally, with Rust-friendly names and ownership: `AtomicLong`, `Semaphore`, `CountDownLatch`, `RateLimiter`. First fix the one piece of shared infrastructure they all depend on: pub/sub subscriptions that are never released.

Scope is exactly the five items the user chose: subscription cleanup, `AtomicLong`, `Semaphore`, `CountDownLatch`, `RateLimiter` (plus `Debug` on public types, which the v0.1 review deferred).

## How Redisson does it (read from its source) and what we copy

| Piece | Redisson | redissun |
|---|---|---|
| Subscription sharing | `PublishSubscribe` keeps one entry per name with a reference count; the last `unsubscribe` removes the entry and unsubscribes from Redis; subscribe and unsubscribe of one channel are serialised by a per-channel semaphore | `PubSub::subscribe` returns a `Subscription` handle. Handles of one channel share one entry. Dropping the last handle unsubscribes. Subscribe and cleanup run under one async lock, and cleanup re-checks the count under that lock, so a new subscriber can never lose its subscription to a pending cleanup |
| `AtomicLong` | plain string, `INCRBY`, Lua `compareAndSet` where a missing key equals 0 | same; stored as a plain integer string, never through the codec |
| `Semaphore` | string counter. `trySetPermits` sets it only when absent. `tryAcquire` is Lua: if value >= n then `DECRBY`. `release` is `INCRBY` then `PUBLISH` the new value on `redisson_sc:{name}`. Permits have no owner | same keys and scripts, channel `redissun_sc:{name}`. `acquire` returns a `Permits` guard that releases on drop (like `tokio::sync::SemaphorePermit`); `forget` keeps the permits taken; `release(n)` stays available |
| `CountDownLatch` | string counter. `trySetCount` sets it only when absent and publishes 1. `countDown` is Lua: `DECR`, delete at or below 0, publish 0 at exactly 0. `await` returns at once when the count is 0, otherwise waits for the message. Channel `redisson_countdownlatch__channel__{name}` | same, channel `redissun_countdownlatch__channel__{name}` |
| `RateLimiter` | hash `name` {rate, interval, type}; counter `{name}:value`; sorted set `{name}:permits` of (id, permits) scored by timestamp; type 0 shared, type 1 per client (keys get a client id suffix). The script drops expired entries, then either records the permits or returns the milliseconds to wait. Callers sleep for that long and retry | same data model and algorithm |

## Deliberate differences

- **Waking waiters.** Redisson publishes a number and wakes `min(acquired, message)` waiters. redissun wakes every waiter on the channel and each retries its Lua script. Simpler, and the retry decides who wins. A slow fallback poll (2 s) covers a lost message.
- **RateLimiter clock.** Redisson passes the client's `System.currentTimeMillis()` into the script, so clients with skewed clocks disagree. redissun uses the Redis server `TIME` inside the script. Needs Redis 5+ (we require 6.2).
- **RateLimiter set encoding.** Redisson packs `(id, permits)` with `struct.pack`. redissun stores `"<uuid>:<permits>"` and parses it with `string.match`.
- **Keys of multi-key objects.** All keys of a `RateLimiter` share a hash tag (`{name}`, `{name}:value`, `{name}:permits`) so one script touches one slot in Redis Cluster.
- **Ownership.** `Semaphore::acquire` and `try_acquire` return a guard instead of requiring a matching manual `release`.

## API

`AtomicLong` (`client.atomic_long(name)`): `get`, `set`, `get_and_set`, `get_and_delete`, `compare_and_set`, `add_and_get`, `get_and_add`, `incr`, `decr`. A missing key reads as 0. Implements `Object`.

`Semaphore` (`client.semaphore(name)`): `try_set_permits(n) -> bool`, `add_permits(n)`, `available_permits()`, `drain_permits()`, `acquire(n) -> Permits`, `try_acquire(n) -> Option<Permits>`, `acquire_for(n, wait) -> Option<Permits>`, `release(n)`. `Permits`: `release(self)`, `forget(self)`, `count()`. Implements `Object`.

`CountDownLatch` (`client.count_down_latch(name)`): `try_set_count(n) -> bool`, `count_down()`, `count()`, `wait()`, `wait_for(timeout) -> bool`. A missing key means count 0, so `wait` returns at once. Implements `Object`.

`RateLimiter` (`client.rate_limiter(name)`): `try_set_rate(RateType, rate, interval) -> bool`, `set_rate(...)`, `try_acquire(permits) -> bool`, `try_acquire_for(permits, wait) -> bool`, `acquire(permits)`, `available_permits()`. `RateType::{Overall, PerClient}`. Asking for more permits than the rate, or using a limiter that was never configured, is an error. Zero permits is `Error::Config`. Implements `Object` by hand because it owns several keys; `rename` returns the new `Error::Unsupported`.

`Debug` is implemented for `Client`, `ClientBuilder`, `Bucket`, `Map`, `Lock`, `LockGuard` and every new type; it prints names and settings, never connection details.

## Testing

Integration tests against real Redis for every method and for each failure mode: wake-up speed (must beat the fallback poll), timeouts, guard drop, concurrency limits (a semaphore of 3 never admits a 4th holder; a rate limiter never admits more than `rate` per window across tasks), per-client versus shared limiting, and subscription cleanup observed through `PUBSUB CHANNELS` (gone after the last waiter, present while one waits, working again after cleanup).

## Out of scope

`PermitExpirableSemaphore`, `Topic`, collections, `MapCache`, read/write locks, rate-limiter `keepAliveTime`.
