# redissun v0.5 design

## Goal

Two changes that the user asked for during v0.4: take the Redis logic closer to Redisson, which is battle tested, and make the waiting API uniform.

## Waiting calls

Every call that can wait is one method that returns a `Pending` value. Await it to wait without a limit. Call `.timeout(duration)` first to wait at most that long, and the call then resolves to `Option`.

| Call | Without `.timeout` | With `.timeout` |
|---|---|---|
| `Lock::lock()` (also `.lease(d)`) | `LockGuard` | `Option<LockGuard>` |
| `RwLock::read()`, `write()` | guard | `Option<guard>` |
| `Semaphore::acquire(n)` | `Permits` | `Option<Permits>` |
| `RateLimiter::acquire(n)` | `()` | `Option<()>` |
| `CountDownLatch::wait()` | `()` | `Option<()>` |
| `VecDeque::pop_front_wait()`, `pop_back_wait()` | value | `Option<value>` |

`try_lock`, `try_read`, `try_write`, `try_acquire` stay as they are. They never wait. `*_for`, `lock_with` and `LockOptions` are removed.

`Pending<'a, T>` wraps a closure that takes the optional timeout. `Lock::lock()` returns its own `LockRequest` because it also has `.lease(d)`.

## HashMapCache like RMapCache

Data model, as in Redisson: hash `{name}`, sorted set `redissun__timeout__set:{name}` (entry to end of its time to live), sorted set `redissun__idle__set:{name}` (entry to end of its idle time). Each value in the hash has its idle time in front: `<idle ms>:<value>`. Redisson packs the same with `struct.pack`. A text prefix is used here so that it does not depend on the machine's byte order.

Scripts follow Redisson's `put`, `get`, `putIfAbsent` and `remove`: an entry is alive when the smaller of its timeout score and, if it has an idle time, its idle score is later than now. A `get` moves the idle score forward. Time is Redis `TIME`, not the client clock.

A background task per cache name deletes expired entries, as Redisson's `EvictionScheduler` does: at most 100 entries per set per run, a pause that starts at `eviction_interval` (default 5 s), doubles up to two hours while there is nothing to delete, and shrinks to a quarter when a full batch was deleted. The task holds only a weak reference to the client core and is aborted when the core is dropped.

Not copied: maximum size with LRU or LFU, entry listeners.

## Testing

All earlier tests were kept and adapted. New tests: idle expiry and the read that keeps an entry alive, `contains_key` that does not, `ttl` together with `max_idle`, the background task deleting entries nobody touches, and a zero `eviction_interval` as `Error::Config`.
